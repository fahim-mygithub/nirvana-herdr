## What is built

1. `src/terminal/program_status.rs` (new): the spec's report parser, revision 0.4, for the root record only. Limits,
   base64, control characters, `state=clear`, `kind`, `app`. Pure and tested.
2. `src/pane/osc.rs`: the pane's OSC tracker reads OSC 7501 reports and the `?` query, OSC 133 `A`, and a full reset
   (`ESC c`). It keeps the latest root record. `src/pane/terminal.rs` answers the query with `ESC ] 7501 ; ? ESC \`
   and hands each change to the pane reader in `ProcessBytesResult`.
3. `src/pane.rs` sends a change to the app as `AppEvent::ProgramStatusReported`.
4. `src/terminal/state.rs`: `TerminalState.program_status`. While it is set its state wins over hooks and detection
   in `recompute_effective_state`. `done` and `error` read as idle, so an unseen one shows as done. The `agent`
   field keeps its meaning: a report sets no agent, so the dead-pane sweep reads the same thing.
5. The pane's shell coming back clears `working`, `blocked` and `idle`, through the existing self-reported
   shell-return probe. `done` and `error` stay, as the spec says, until replaced, cleared or reset.
6. `pane list` and `agent list` carry the record in `tokens`: `program_status` (the state word) and
   `program_status_msg` (the decoded message). No schema change.
7. `herdr seat exec` in a pane writes reports to its own terminal: `working` with the order id, then `blocked` when
   the order ends asking, `done` when delivered, `error` when it failed or was stopped, `idle` when it waits for a
   window to reset, and a clear when this pane ran nothing (another pane's live worker, no such order). It also writes OSC 7
   with its folder, so the pane's cwd is the order's. A detached `seat exec` writes neither: its stdout is a log.

## The stale folder had its own cause

herdr takes a Windows pane's folder from its last bare PowerShell prompt (`windows_powershell_current_prompt_cwd` in
`src/pane/terminal.rs`). The launch line (`exec_line` in `src/nirvana_worker.rs`) runs `Set-Location` and `seat exec`
on one line, so no prompt shows the new folder until the worker ends. Measured on the scratch session: the line
`Set-Location order2; Start-Sleep 12` read the old folder while it ran. With `seat exec` writing OSC 7, the same shape
read the new folder while it ran.
