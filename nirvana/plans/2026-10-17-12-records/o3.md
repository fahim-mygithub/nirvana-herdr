## What was built

- `src/nirvana_run.rs`: the project's `.nirvana/` folder and its `.gitignore`; the journal (events, the lock, `seq`);
  `replay` to a `RunState`; the decisions with no model (`rate_decision`, `stalled`, `restart_delay`, `check`,
  `interrupted_steps`, `wake_decision`, `prompt_line_text`); the receipt and its text; the record line; the CLI
  `herdr run status|wake|notice|check|resume|tick|receipt|end|log`; `note_owner_key`, which the server calls.
- `src/nirvana_worker.rs`: the Work Report schema and its check; the launch argv of claude and agy; the stream reader
  (session, usage, text, tools, rate limits, the result); agy's `AGY_ERROR`; the live lock; the job object; one
  attempt (`run_attempt`) and the supervisor loop (`exec`): delivery, failure, stop, stall restarts, rate limits; the
  re-seat brief and booking; panes through herdr's own CLI; the CLI `herdr seat run|exec|status|read|stop|cleanup`.
- `src/nirvana_seat.rs` (O2's): `RecordLine` gains optional fields, the booked pick's details, the herdr version, a
  journal reference and a flattened `extra` map that keeps unknown keys (O2 review S5); `recorded`, `fill_from_lease`
  and `record_once` (lock, refuse a recorded order, fill from the live booking, append, release), which `herdr seat
  record` and the runner both use; `table()`; `live_world` made public; the `seat` verbs above routed to
  `nirvana_worker`. The journal's lock is O3's own OS file lock, so `Lock` stays as the O2 fix round will change it.
- `src/server/headless.rs`: one `Nirvana fork:` hook after the server forwards an owner's key to a pane.
- `src/main.rs`: the `run` arm.

## Choices where the plan was silent

1. **The raw stream** goes to `runs/<run>/streams/<order>.jsonl`, beside the journal, not into it. The journal holds
   the typed events read from it (usage, a rate limit, the report, the session). Every event of the brief's list is
   in the journal; a full stream in it would make the single-writer journal large and the receipt's replay slow, and
   O5's "the quote is in the worker's stream" check reads one file per order.
2. **An `opened` event**, beyond the brief's list: the run's project, its orchestrator's pane (`HERDR_PANE_ID` of the
   first `seat run`), auto mode, and the pools from `usage.json` at the start.
3. **The deferral's timer** is the worker's own supervisor, which waits in its pane and resumes the worker's own
   conversation (within its own seat, §7.2), plus `herdr run tick`, which starts a due deferral whose supervisor is
   gone. Tick is for O4b's hooks to call. Not herdr's server: the fork's reload restarts the server, and a timer there
   needs hooks in its loop; the journal is what survives, and tick reads it.
4. **`seat run <seat>` must agree with the rule.** With no booking, it picks for `--class`; a different seat needs
   `--reason`, which makes it an override (3 a run, O2's rule). With a booking from `seat pick --book`, it uses it.
   `--not-family` is passed through and kept on the order, so a re-seat keeps it.
5. **Auto mode is on** unless `--no-auto` (R6: "Auto mode for both is fine").
6. **A re-seat's child** is `<order>-r<n>`, in the parent's worktree, with a brief: where it stopped, the diff's path,
   the last turn quoted, then the original order. Its record line has the outcome `reseated`.
7. **The spent pool** is excluded from the re-seat by a reading of `used = 1.0` put first in O2's world, so the floor
   skips every seat on that pool; the signal's window when it names one, every window of the pool when it does not
   (agy's exit 3).
8. **What counts as an order moving forward** for the wake cap: `seated`, `gated`, `merged`, the run's `ended`. A
   delivery is a worker's progress, not the orchestrator's answer to a wake. `run notice` (the prompt hook) does not
   count as a wake.
9. **The busy rule**: a follow-up queues while herdr says `working`; `--urgent` (the owner's stop) steers. A
   `blocked` pane always queues; an unknown state queues.
10. **The owner's last key** is written by the server, at most once a second per pane, to `<home>/nirvana/keys/<pane>`,
    keyed by the pane's public id, which is `HERDR_PANE_ID`.
11. **The record line** is written once per order and run: at `gated` or `merged` through `run log`, when a worker
    fails or is re-seated, and at `run end` for what is left. The booked pick's details also ride on `seated`, since
    the lease that held them is released when the worker ends, before the gate rules. "pass" is the gate's word; O2's tally counts every other
    word as a failure, `reseated` and `failed` included (O5 names the gate's words).
12. **Usage events** are at most one in 10 s and none before the first token; each holds the attempt's cumulative
    tokens, and the order's tokens are the last of each attempt, summed. agy's `output_tokens` holds its thinking
    (P4's `total_tokens` is input plus output).
13. **`run end`** reads stale usage readers again (0 tokens, about 4 s) for the end figure; the start figure is the
    cache as it was, with its `read_at`.
14. **`herdr run log`** takes only gated, merged, asked and the orchestrator's own usage; every other kind is herdr's.

## Controls

73, in `nirvana/controls.d/o3.py`, one per assertion. Each run alone with `controls.py --only <exact name>` from a
list argv, names stripped of carriage returns, the expected result (every one PASS, the tree unchanged) written before
the run. The second round, after the record work, ran all 73: 73 of 73 reddened their test. In the first round, of
the 65 then, 63 reddened on the first run. Two did not, and were wrong:
- `run_wake_into_blocked` did not compile (`let _ =` without its `;`); rewritten to empty the blocked arm. PASS.
- `worker_stop_kills_one_process` swapped `job.kill()` for `child.kill()` and stayed green, rightly: dropping the
  kill-on-close job ends the tree anyway. Its replacement `worker_tree_outside_the_job` first read
  `Assign(...) == 0 && false`, which still called `Assign`, and stayed green; as `false && Assign(...)` the stop took 56
  s against 0.6 s. PASS.
`git status --porcelain` was the same after each.

  with its caller.

## Merge onto alpha 0.15.0, and the wake guard

Rebased 2026-10-18 onto master 14a71d9a (O1, O2 with its fix round, O6, O4a) by the leaf "Opus 5.5 high - O3 merge
and wake guard". Not merged into master; the version is the orchestrator's to bump.

**Conflicts.** `src/main.rs`: O4a's `nirvana` arm, O6's `media` arm and O3's `run` arm, each closed. `src/nirvana_seat.rs`:
`Lock` is the fix round's (`File::try_lock`, no stale rule, no `Drop`); the first O3 commit's `try_take_named` was kept
in that form so the commit builds, and the second removes it as before; USAGE keeps the fix round's exit lines and adds
O3's verbs. `nirvana/CHANGELOG.md`: O3's NEXT entry on top.

**Adapted to the fix round.** `seat run`'s booking (`nirvana_worker::book`) set `overrides += 1` with no time, which the
fix round's 8-day prune reads as an old run and drops; it now books through `book_pick`, and refuses an unknown
`--needs` or `--not-family` word (exit 2). `book`, `book_child`, `release_lease` and `record_once` load `leases.json` with
`load_leases`; the lossy `read_leases` is removed. `record_once` still records an order whose `leases.json` does not
parse, leaving the file as it is and saying so on stderr. Control `record_booking_kept` follows the new release line.

**The wake guard.** A wake types only into a pane that runs Nirvana Claude: `pane get`'s `agent` is `claude`, and a
`pane process-info` foreground process has `--agent nirvana` with `--plugin-dir` equal to this home's `nirvana/claude`
(folder key, case and separators ignored). `wake_decision` queues for any other pane, urgent or not, before the busy
rule; `type_prompt` reads the pane again just before `herdr agent prompt`. The argv is the signal because it is the only
reading that tells Nirvana Claude from plain Claude Code, the incident's pane; herdr exposes no process environment, and
`NIRVANA_ORCHESTRATOR=1` reaches Claude's tools through settings.json when the verb's seeded shell starts it, not
`claude.exe`. The agent check is kept beside it because `process-info` on Windows answers from a cached process
snapshot while herdr's agent label drops when the agent exits. The runner's only other typing, `open_pane`'s `pane run`,
goes into the shell of the pane the same call created, so it is not guarded by this check (it would refuse every
worker). The test reads `pane get` and `pane process-info` recorded from an isolated server's four panes
(`src/nirvana_run/fixtures/panes/`): Nirvana Claude with O4a's argv, plain `claude`, pwsh, `agy`, each Claude and agy on
its folder-trust screen in a scratch repository, nothing typed.
