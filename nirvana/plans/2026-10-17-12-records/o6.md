## 2. What was built

- **`src/nirvana_media.rs`** (new) and **`src/main.rs`** (`mod nirvana_media;` + `"media"` CLI dispatch arm):
  - `herdr media probe <file> [--json]`: invokes `ffprobe -v error -print_format json -show_format -show_streams <file>`
    with a list `argv` (never through a shell) and reports `duration_secs`, `size_bytes`, `container`, `video_codec`,
    `width`, `height`, `resolution`, `audio_present`, `audio_codec`, `limit_bytes` (`100,000,000`), and `over_limit`.
    Exits `2` with a clear message when `ffprobe` is missing on `PATH` or the file is missing/unreadable.
  - `herdr media shrink <file> [--out <path>] [--max-mb 95] [--json]`: probes duration with `ffprobe`, computes a target
    video bitrate with `target_video_kbps(duration_secs, max_bytes)` leaving a 15% safety margin (`SAFETY_MARGIN = 0.85`),
    deducting mono audio (`48` kbps), and clamping to `[32, 4000]` kbps. Runs `ffmpeg` with a list `argv` to downscale
    to at most `1280` px wide (`scale='min(1280,iw)':-2`), cap frame rate at `10` fps (`-r 10`), encode H.264 `yuv420p`
    with VBV rate control (`-b:v`, `-maxrate`, `-bufsize`), and keep mono 48 kbps AAC audio (`-ac 1 -b:a 48k`). Writes
    `<stem>.shrunk.mp4` next to the input by default and refuses any output path that collides with the input. If pass 1
    still exceeds `max_bytes`, retries once at a lower video bitrate (`retry_video_kbps`, 60% of pass 1 or the measured
    overshoot ratio).
  - `herdr media prompt <file> --ask "<question>" [--seat argon|flash]`: prints a single-line prompt for an `agy` worker
    resolving `<file>` to its full absolute path, instructing the worker to open it with `view_file` (`AbsolutePath`,
    omitting `StartLine` and `EndLine`) without starting subagents or background commands, and requesting (1) `MM:SS`
    timestamps, (2) what happens on screen and any spoken transcript, (3) visual details a text transcript alone would
    lose, and (4) findings answering `<question>`.
- **`nirvana/claude/skills/media/SKILL.md`** (new, 79 lines): Claude Code skill teaching the Nirvana Claude orchestrator
  to probe first, shrink when `over_limit` is true, seat via `herdr seat pick --class media.video|media.audio|read.huge`
  (or `--needs video` on visual classes), generate the worker prompt via `herdr media prompt`, resume `read.huge`
  sessions by `--conversation <id>` for read-only follow-ups, never read media or huge files into its own context, and
  fail any empty worker response even when `status: SUCCESS`.
- **`nirvana/controls.d/o6.py`** (new): 22 sabotage controls covering every assertion across the 5 unit tests.

## 4. Choices where the plan was silent

1. **`1 MB = 1,000,000` decimal bytes (`MB_BYTES = 1_000_000`, `VIEW_FILE_LIMIT_BYTES = 100_000_000`).** Using decimal
   megabytes rather than binary MiB (`104,857,600`) is conservative: any file under `100,000,000` bytes (and any shrink
   under `95,000,000` bytes) is guaranteed to pass `view_file` whether `agy` checks decimal MB or binary MiB.
2. **Bitrate safety margin and clamps (`SAFETY_MARGIN = 0.85`, `MIN_VIDEO_KBPS = 32`, `MAX_VIDEO_KBPS = 4,000`,
   `AUDIO_BITRATE_KBPS = 48`, `RETRY_BITRATE_FACTOR = 0.60`).** Leaving 15% headroom plus VBV rate control (`-b:v`,
   `-maxrate`, `-bufsize 2x`) keeps single-pass encodes under `--max-mb` on noisy inputs; clamping `[32, 4000]` kbps
   prevents sub-second clips from requesting hundreds of Mbps and multi-hour clips from passing `-b:v 0k` to `ffmpeg`.
3. **Retry bitrate uses `min(0.60 * pass1_kbps, pass1_kbps * (max_bytes / actual_bytes) * 0.85)`.** If pass 1 overshoots
   by more than 40%, scaling by the measured overshoot ratio brings pass 2 under the limit in one retry.
4. **Default `--seat` for `herdr media prompt` is `argon`.** Matches `media.video` in `seats.toml`, where `argon`
   (`score = 90`) precedes `flash` (`score = 82`).
5. **Verbatim prefix stripping (`\\?\`) on Windows paths.** `std::fs::canonicalize` on Windows prefixes paths with
   `\\?\`; `absolute_media_path` strips that prefix so `view_file` receives a clean `C:\...` path.
