## 5. Choices where the brief was silent

1. **Arm C and the permission mode.** M2 and M5 carry `claude_code.extra_argv ["--permission-mode", "auto"]` in the
   scenario file, with the measurement as its `why`; M1 keeps the brief's argv. A permission denial in the result row
   is an incident (`permission_denied`) and shows in the table.
2. **Where a run ends.** `EndDetector`: busy = herdr `working`, a spinner line, text on the prompt line, or any run
   class in `live|deferred|queued|gate|unknown`; blocked = herdr `blocked` or a permission or trust screen, which is
   never quiet and ends the run as `stuck_blocked` after 120 s; quiet must hold 20 s and 2 samples; the wall is when
   the quiet BEGAN, so the settle time is not in it; an ask that produced no busy sample in 60 s is `no_response`, not
   a pass. A run left unended (`finished_unended`, `stuck`, `none`, `wake_cap`) ends the wait and is an incident; the
   driver then ends it (`herdr run end`) so a receipt exists, and says so in `driver_ended_runs`.
3. **The person policy.** The scenario's `reply` ("Yes." for M5) is typed, at most 3 times, when the orchestrator ends
   its turn on a paragraph that ends in `?`; each is a `person_reply` incident and counts in `person_actions`.
4. **Stall.** Working with no write to a transcript, a subagent transcript or a journal for 300 s: the spinner's own
   clock changes the screen every second, so the screen cannot show it.
5. **Scratch home.** One per run, so `record.jsonl`, the board and `usage.json` start the same; the owner's
   `usage.json` and `seats.toml` are copied, never written.
6. **Pool readings.** `herdr usage --json --refresh` through the scratch home before and after (0 tokens, a few
   seconds). Claude's windows read in whole percents and are the whole account's, so another agent's use in the span is
   inside them; the table says so.
7. **The truth reads the clone before it is removed;** `git-final.txt` keeps the log, status, worktrees and branches.

## 6. Controls

`nirvana/controls.d/o7.py`, one per assertion. Expected result written before the first run: every control PASS (the
named test prints its `FAIL: <test>` line; an ERROR is not a red line), the sabotaged files restored, and the SHA-256
of `ab.py`, `M1.py`, `moto.json`, `test_ab.py` and `o7.py` the same before and after the batch. Each ran alone with
`controls.py --only <exact name>` from a list argv (`scratchpad/run_controls.py`, names read from `--dry-run`, which
cannot carry a carriage return).

- First batch: 82 of 86 as expected. Four were not: `o7_env_no_browser` and `o7_home_moves_owner_file` and
  `o7_home_no_plugin` made their test ERROR instead of FAIL (the test read a missing key or file), and

  (`assertIn`, `is_file` first, an inherited value set), and `o7_home_no_plugin` also found a real fragility
  (`seed_home` relied on `copytree` to create `home/nirvana`; it now makes the folder).

  does not end it), and `o7_tokens_cache_kinds_swapped` green (the fixture had zeros for both cache kinds); both got a
  test that discriminates.
- Final batch: `PASS` for every `o7_*` control, files unchanged (`target/o7-bench/controls-run2.log` plus the two
  re-runs above); `git status --porcelain` before and after identical.

Run it from the `o7-ab` worktree (the plugin dir defaults to `nirvana/claude` there; `--plugin` overrides). The out
directory must not have spaces. It refuses to start a run when Claude's 5 h window is above 80% or its week above
85% (exit 3, `guard-*.json` written), and when a reading is missing (`--allow-unknown-window` overrides). It resumes:
an existing `runs/<scenario>/<arm>-<k>` is skipped. M5 (up to 3600 s per run) is the longest.
