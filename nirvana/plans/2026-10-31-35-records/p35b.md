## Where the plan was wrong or silent

1. **`sse` is refused on agy.** The plan allows stdio, http or sse (§3.2). No probe measured sse, so it is refused, which
   is stricter than the plan. Owner's call to widen after a probe.
2. **A key outside `SERVER_KEYS` refuses the server on agy.** The plan lists only the keys to translate. Dropping an
   unknown key such as `disabled` or a timeout could change the server, and agy's `--settings` refused an unknown key at
   parse (plan probe 1). This is also stricter than the plan.
3. **`read_file(*)` may deny writes too** (probe 2). A `Read` denial on agy can therefore deny more than Claude's. It
   never denies less, so the row is kept, and the table's comment says so.
4. **`command(*)` shows up in the denial as `unsandboxed(...)`.** The rule still holds. The live check 5 text
   "Matches user-configured deny rule" is the same.
5. **The drive-stripped path form the docs describe is not what herdr writes.** It was not separated from the
   `read_file(*)` denial. Probe 1 measured the drive-kept form alone.
6. **The plan does not say to remove the folder before an attempt or after a failed argv build.** Both are done. A
   stale folder from a crash would otherwise reach the next start. An error in `with_profile` after `order_argv` wrote
   the servers would otherwise leave the token-bearing definitions until the run's cleanup. The second applies to
   claude's plan 29 file too.
7. **`key_clash` still refuses at the seat for either CLI.** On agy it is moot, because agy names tools by server name.
   I left it as it is, since `seat_needs` does not know the CLI.

### Where the order or the plan was wrong, or could not be followed

1. **S6 is not resolved against `.mcp.json`.** The mapping is read at seat time by `nirvana_profiles::narrow`, whose
   callers in `nirvana_seat.rs` (`pick` args) and `nirvana_gate.rs` (send-back) pass no root, and those files are not
   P35b's. A resolver at exec alone would let the seat rule put an order on agy that the exec then fails, and
   `seat_order_with` already refuses a pick the rule would put elsewhere ("the rule seats this order elsewhere"). The
   rule built is the review's second option and needs no list: it maps only names whose server part flattening cannot
   have changed, so it never denies less than Claude's. Cost: a server named with `_` or `.` cannot be denied on agy.
   Widening it is a seat-rule change across three files.
2. **S2's "journaled line" is the delivered `Ended` event's `why`.** The journal has no free-text kind, and
   `nirvana_run.rs` is not P35b's. `replay` keeps a delivered order's `why`; the timeline line prints only a
   non-delivered end's.
3. **S4's sweep lines are not journaled.** They go to the sweeping supervisor's view. A sweep removes files of an order
   that already ended; it has no event of its own to hang on.
4. **The lesson review on agy is held less than a claude one.** `nirvana_review::DENIED` names eleven tools; agy gets
   `command(*)` and `write_file(*)`, and whether `write_file(*)` stops `edit_file` is unmeasured. The plan chose this
   (§3.4); before plan 35 the agy review had no deny at all. The gate's lessons-folder check is the backstop.
5. **The order's "five controls go red alone"** holds for the hunks as applied; each was run alone (below).

### What still waits for cleanup

- An order still seated, running or deferred whose supervisor died (no lock held) keeps its files until its next
  attempt removes them before starting, or `herdr seat cleanup`, or a later supervisor after the order ends.
- A run whose journal is gone is not swept (`Project::runs` lists only runs with a journal).
- A project where no `seat exec` runs again keeps its leftovers. They stay git-ignored only while `.nirvana/.gitignore`
  says `runs/`; `ensure_dir` writes that file only when it is missing.
- On Windows the files take the project folder's ACL (plan 29 F2, unchanged).

### Unmeasured, still

- `edit_file` under a `write_file` deny, and under `write_file(<tools>/)`: the model could edit the tools folder's
  `AGENTS.md` or `mcp_config.json` in place. Both are rewritten before each attempt.
- `write_file(<run>/agy/)` for a file two levels down (`<tools>/.agents/mcp_config.json`): the docs call a directory
  rule recursive; probe 1 measured one level.
- Whether agy reads parent folders' `AGENTS.md` or `.agents/skills/` at all; `workspace_dirs` keeps the plan's walk.
- A Claude tool name whose real MCP tool name had a character Claude flattens (the API admits only letters, digits,
  `_` and `-`): the agy rule names the flattened tool and may match nothing.
