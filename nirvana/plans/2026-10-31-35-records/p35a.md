## What was built

  `Invoke-RestMethod`. Substrings, case-insensitive, looked for outside the segment's URLs, as before.

  The p24 control `p24_shell_fetch_words` finds that const verbatim, in a file this package does not own. No false
  `iwr` hit is known. The report holds the hunk if the owner wants `iwr` moved.
- `gh_read_urls` (new): in a segment, `gh api <endpoint>` (flags skipped, and the value of `-X`, `--method`, `-H`,

  `https://api.github.com/repos/<o>/<n>` and, **beyond §5 item 2**, the endpoint itself,
  `https://api.github.com/repos/<o>/<n><rest>`. That is the URL gh fetched. asl-report cited
  `https://api.github.com/repos/Crazycatz67/asl-recognizer/license`, read with `gh api repos/.../license`.
  `gh repo view <o>/<n>` (or its github.com URL, `.git` dropped) reads the two repository URLs. `gh search` reads
  nothing.
- The cut is unchanged: newlines, `;`, `|`, `&&`. agy's `call_mcp_tool` check is unchanged.

### What was built (all in `src/nirvana_gate.rs`)

- **Stable ids** (`stable_id`). A cited source has a stable id when it is one of these:
  - a YouTube video: `watch?v=`, `/shorts/`, `/embed/`, `/live/`, or `youtu.be/`, with exactly 11 id characters;
  - a Reddit post: `/comments/<id>` or `redd.it/<id>`;
  - a GitHub repository: `github.com/<o>/<n>` or `api.github.com/repos/<o>/<n>`, and nothing deeper;
  - a local path: `file:///...` or `C:\...`.
- **Where a stable id counts** (`stream_reads`, `stable_read`):
  - anywhere in the text of a command that fetches, or in that command's output. "Fetches" means the whole command
    holds a fetch word outside its URLs, or runs a `gh` read;
  - in the call or output of a fetch tool: agy's URL and browser tools, and Claude's WebFetch and browser MCP calls;
  - in a Claude Bash fetch's `tool_result`;
  - a path counts only when agy's `read_file`/`view_file` or Claude's `Read` opened exactly that path. Case and
    separators are ignored.
- **A plain URL** keeps the per-segment rule. It also counts when it is a URL in a fetch's output: the page or its
  redirect came back. reveal-gemini printed each resolved vertexaisearch URL, and body-extrapolation printed
  `FETCHED: <url>` and `<url> -> 200`.
  - Unlike the orchestrator's "anywhere in the command" rule, a plain URL in a fetching command's text does **not**
    count. That keeps plan 24's per-segment test (`curl a; echo <url>` fails) and §5 item 1's rule.
  - The cost of that choice, measured: reveal-gemini counts 17 of 18 instead of 18.
- **New fetch words:** `yt_dlp`, `yt-dlp` and `YoutubeDL` (`VIDEO_FETCH_WORDS`). They count per segment as well.
- **`Owns:` in any case** (`strip_key`). reel-motion-gemini's `Owns:` line had been read as "names no owned file".
- **A sources send-back** opens with `SOURCES_REDO` instead of "do not start over". It says none of the cited
  sources is trusted, each must be opened again, and every claim resting on a source that cannot be opened is
  redone. Any other send-back keeps "do not start over".
- **The owned axis in the project folder** (`order_changes`):
  - **With a seat snapshot.** `write_seat_snapshot` writes `gate/<order>.seat-dirty.json`: each dirty path with its
    size and modification time. A path counts only when it is new since seating, or its size or time changed. The
    snapshot belongs to the chain root, so a send-back is checked against the first seating.
  - **Without a snapshot** (an order seated before this change, r2 among them): a path counts when it was modified at
    or after the root's `seated_at`. A deletion does not count, because the gate cannot tell when it happened.
  - **With neither a snapshot nor a seating** (the older tests): the whole dirty tree, as before.
  - `seat run` must write the snapshot. That is `nirvana_worker.rs` (P35b's file), so it is a hunk in the report.
    Until it lands, every project-folder order takes the no-snapshot path.

### `Seated` comes before the worker (S3, read only in `nirvana_worker.rs`)

`seat_order_with` writes `Kind::Seated` in `journal.transact(now(), ...)` and only after that calls `launch_worker`
(about line 3502, then 3516). The rate-limit re-seat (about line 2125, then 2148) and the gate's send-back child
(`nirvana_gate.rs`, about line 3232, then 3239) do the same. `seated_at` is that `now()`, in whole seconds, and the
fallback counts a file whose time is in that second or later. Nothing the worker writes can be older than its
seating. The snapshot hunk goes after the transaction and before `launch_worker`; applied here for one fmt and
clippy run, with the `dead_code` attribute dropped, both exited 0, and the file was restored.
