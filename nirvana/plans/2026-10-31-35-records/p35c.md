## Where the plan or the order was wrong, or silent

1. **`browser` cannot reach agy until R2.** The plan says "A need `browser` or `bladebro` grants it", and `browser` is a
   capability only opus and sonnet have (`nirvana_seats.toml`), so `--needs browser` always seats on claude. On agy only
   `--needs bladebro` grants it. The SKILL.md line the plan asked for ("`--needs browser` gives the worker bladebro on
   any seat") would be untrue today; hunk H3 says what is true.
2. **`BLADE_PLAIN=1` is in decision 0043's code (`nirvanad/workers/browser.py`, "no ANSI in what the worker reads") and
   not in the plan's R1 list.** Built as the plan lists (five variables); adding it is the owner's call.
3. **The class no longer gives the line.** Plan 25's `browser_line` gave it for a class token `browser`; item 3 says the
   line goes to a granted worker and no one else, and only a need grants. No class in `seats.toml` is named `browser`,
   so nothing that seats today changes. `agent-browser` as a need now gets no line either; it was already refused at
   seating as an unknown word.
4. **Ownership differs from the plan.** The plan gives P35c `nirvana_worker.rs` and `seat/SKILL.md`; the work order does
   not (plan 37 uses them). Their changes are hunks H1-H3. `nirvana/controls.d/lean.py` and `gui_tools.py` are no
   one's in either; their changes are hunks H4-H5.
5. **The plan's `nirvana_seats.toml` change has no historical default.** `HISTORICAL_DEFAULTS` ends at v6, which is
   already older than master's default (plan 34a's review round changed it without adding v7), so an unedited 0.49.0
   table is not upgraded by this `why` either. Adding `src/nirvana_seats_v7.toml` (master's bytes) and its
   `include_str!` in `nirvana_seat.rs` is outside this package; it is a text-only line, so I left it.
6. **agy's init line lists 60 tools, browser tools and `read_url_content` among them**, here and in all of P35b's
   probe streams, against §1.2's "14 built-ins ... no URL reader and no browser". P35b's probe 5 showed the init list
   is not what the model is offered (it named `edit_file`, which the list lacks). Whether agy's own browser tools work
   in print mode was not tried (one page, and not this package's question).
