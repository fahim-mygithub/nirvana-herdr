# Feature 11: Accounts, a sign-in button at the foot of the sidebar

## Ledger

| # | Verbatim quote | Surface | Owner | Verifier |
|---|---|---|---|---|
| L1 | "In the bottom left let me manage my login accounts." | an "accounts" button on the last row of the sidebar foot, under usage; it opens the Accounts panel, which shows who is signed in to each CLI | orchestrator | rendering tests on the foot and the panel; live in a herdr window |
| L2 | "Create a button so that this herder instance let me login to claude code or antigravity or codex." | each panel row has a button ("log in", or "switch" when signed in) that opens a new focused tab running that CLI's own sign-in | orchestrator | the server opens the tab with the helper's argv (test); the helper's steps per CLI (tests); live: the tab opens and the CLI's sign-in starts with no browser (`BROWSER` set to a no-op in the probe) |
| L3 | "I currently have a new antigravity account I want to login to." | Antigravity's switch: the tab starts `agy`, waits for its prompt, types `/logout` and Enter; agy's own sign-in follows and the owner picks the new account in the browser | orchestrator | the typing is tested with `/help` on a live agy (a logout would sign the owner out); the owner's own press is the live run of `/logout` |

## Measured before building (2026-10-17)

- **Claude Code 2.1.301**: `claude auth status` prints JSON (`loggedIn`, `email`, `subscriptionType`) in 0.2 s;
  `claude auth login` signs in and replaces the stored account; `claude auth logout` exists.
- **Codex 0.42.0**: `codex login status` prints "Logged in using ChatGPT" (no email; the email is only in `auth.json`,
  a credential file herdr does not read); `codex login` signs in with the browser.
- **Antigravity CLI 1.4.0**: no login subcommand. `agy -p /help` lists what print mode answers; `/logout` is not
  among them. The sign-in lives in the interactive screen, its token in the system keyring, so there is one account per
  Windows user and no profile folder to swap. `agy -i "/help"` sends "/help" to the model as a prompt; it does not run
  the command. Typed into a running agy, "/help" then one Enter runs the command (pane read, scratch session). The
  account is in agy's log: `~/.gemini/antigravity-cli/log/cli-*.log` holds
  "OAuth: authenticated successfully as <email>" on every run, including herdr's five-minute `/usage` read.

## Shape

- **The button**: the foot's last row, " accounts", in the accent colour. A click opens the panel; a second click
  closes it.
- **The panel** is drawn over the pane area, at its bottom left, beside the button. One row per CLI: name, who is
  signed in ("you@x · max", "ChatGPT sign-in", "not signed in", "not installed"), and the row's button. ↑/↓ choose, Enter
  or a click on the button signs in, Esc closes. The accounts are read on a worker thread when the panel opens and
  every 10 s while it stays open; herdr reads nothing while it is closed.
- **Signing in** sends herdr's existing `command.invoke` with id `nirvana.account_login:<cli>`, as Preload's edit does.
  The server opens a new focused tab, "log in <CLI>", running `herdr account login <cli>`:
  - Claude: `claude auth login`, then `claude auth status`'s account.
  - Codex: `codex login`, then `codex login status`.
  - Antigravity: `agy`; when its banner is on the pane's screen, herdr types `/logout` and Enter into that pane (only
    when someone is signed in), and agy's own sign-in follows. When agy exits, Enter starts it again, for the case
    where agy quits after the logout instead of showing its sign-in.
  - Then "Press Enter to close this tab."
- herdr never reads, stores or moves a credential: it runs each CLI's own sign-in and reads only what the CLI prints
  (and agy's log line).
- Not in this feature: logging out from the panel, several saved accounts per CLI (Claude could do it with
  `CLAUDE_CONFIG_DIR` profiles; agy cannot, its token is in the keyring).

## Record

Built 2026-10-17 on alpha 0.10.0 (f52dda9b) as alpha 0.11.0.

1. **`herdr account status`** on this PC: Claude "<email> · max", Codex "ChatGPT sign-in", Antigravity "<email>".
   The first reading said Codex "not signed in": `codex login status` writes to stderr. Fixed, and Claude's JSON is
   now cut from whatever stderr adds.
2. **In a herdr window** (scratch home, `BROWSER=where.exe`, a scratch `CLAUDE_CONFIG_DIR` and `CODEX_HOME`,
   `NIRVANA_ACCOUNT_TYPE=/help`): a click on "[ accounts ]" opened the panel at the bottom left of the panes with the
   three rows (leaf "Haiku - read accounts screenshot"); a click on Antigravity's "[ switch ]" opened the focused tab
   "log in Antigravity". The first build typed nothing: in a 120-column pane agy draws its logo on the banner's lines,
   and the match wanted the email at the start of a line. Matched as a word since; on the rebuilt build herdr typed
   `/help` and Enter and agy opened its help. After `/exit` the tab offered to start agy again; `q`, then
   "Now: <email>", then Enter closed the tab.
3. **Claude**: "[ log in ]" (the scratch profile is signed out) opened "log in Claude Code", which ran `claude auth
   login`: "Opening browser to sign in", the fallback link, "Paste code here if prompted". Browser processes 60
   before and after; the tab was closed at the paste prompt, no credential was written to the scratch profile.
4. **Codex**: not pressed live. Its sign-in may not honour `BROWSER`, and the owner's browser is signed in.
5. 11 new controls redden their tests (10 `accounts_*`, `header_name_pad`); 176 controls find their lines; the suite
   passes but the one upstream test that failed before.

**Not measured.** A real `/logout` and what agy shows after it (sign-in screen or exit): it would sign the owner out.
The owner's own press of "[ switch ]" is that run.
