## What was built

1. **§2: Orchestrator usage logging via hook**
   - Implemented `read_transcript_usage(path: &Path, offset: u64) -> std::io::Result<(Tokens, u64)>` in `src/nirvana_claude.rs`. Reads assistant lines, extracts `message.usage`, deduplicating across identical `message.id`s and taking the max per slot.
   - Added subcommand `log-usage` to `src/nirvana_claude.rs` CLI and registered in `nirvana/claude/hooks/hooks.json` under `SessionStart` (for `source == "resume"`, timeout 15) and `Stop` (after `jev compact`, timeout 15).
   - Skips when `agent_id` is set, `NIRVANA_ORCHESTRATOR != 1`, or cwd is inside `.nirvana/worktrees`.
   - Appends `Kind::Usage { order: None, attempt: 0, session, tokens }` to the most recent open run of the project, advancing byte offset stored in `<home>/nirvana/usage-offsets.json`.
   - The run receipt already formats `state.orchestrator` tokens, displaying them instead of "missing".

2. **§3: Nirvana Claude own-edit limit**
   - Defined pure function `edit_budget(baseline: &EditState, now: &EditState, limit: EditLimit) -> Option<String>` enforcing at most 1 file and 30 lines outside an order (added + deleted lines; untracked files counted by lines).
   - Filtered out of scope: `.nirvana/`, `.claude/`, memory paths, absolute or parent paths, and cwd in `.nirvana/worktrees`.
   - Added `prompt-baseline` subcommand registered on `UserPromptSubmit` (timeout 10) capturing baseline state into `<home>/nirvana/edit-baselines.json`.
   - Added `guard-edit` subcommand on `PreToolUse` for `Edit|Write|MultiEdit` blocking any single call exceeding 30 lines.
   - Added `check-edit` subcommand on `PostToolUse` for `Edit|Write|MultiEdit|NotebookEdit|Bash` checking whole project diff against baseline and blocking with rule R2 explanation if limit is exceeded.
   - Updated `nirvana/claude/ROLE.md` stating the 1 file and 30 line limit and pointing at the hooks.

3. **§4: Preserving model and effort override across retries**
   - In `nirvana_gate::send_back`, propagated `seated.override_reason` to child request as `override_seat = (<parent seat>:<parent effort>, <parent reason>)` and marked `inherited_override = true`. Set `child.override_reason = seated.override_reason.clone()`.
   - In `nirvana_seat::book_pick`, avoided incrementing `leases.runs.entry(run).overrides` when `pick.inherited_override` is true.
   - In `nirvana_seat::pick`, exempted `request.inherited_override` from the `world.overrides_used >= constants.overrides_per_run` check.
   - In `nirvana_worker::rate_limited`, checked if rate limit occurred on `seated.pool`. If limit pool matched `seated.pool`, dropped override; if on another pool, retained override and set `inherited_override = true`. Journal line names whether override was dropped or kept.

4. **§5: Gating research and media orders on sources axis**
   - Added optional `sources` array of `{url, used_for}` to `REPORT_SCHEMA` and `REPORT_KEYS` in `src/nirvana_worker.rs`.
   - Added `sources_axis` in `src/nirvana_gate.rs` for `research.*` and `media.*` classes: fails if report has no sources; checks each source URL against fetch/read/browser calls in worker stream after trimming trailing `/` and fragment.
   - Updated `nirvana_run::end_cli`: checks `delivered_ungated(&state)` and refuses with exit 2 if any delivered order is ungated.
   - Supported `herdr run end --abandon <order> --why <text>` to record an `abandoned` verdict so the run can end cleanly.
   - Updated `nirvana/claude/skills/gate/SKILL.md` documenting the sources axis and `--abandon`.

5. **§6: Requiring `owns:` line for build, fix, and plan orders**
   - Added `requires_owns(class: &str) -> bool` for `build.*`, `fix.*`, and `plan`.
   - In `nirvana_worker::seat_order`, refused orders missing `owns:` for those classes with exit 2: `"a build order needs an \`owns:\` line naming the files it may change"`.
   - In `nirvana_gate::owned_axis`, empty `owns` for `build.*`, `fix.*`, and `plan` returns `Mark::Fail` (`"unbounded: the order names no owned file"`), while other classes retain `Mark::Note`.
   - Documented requirements in `nirvana/claude/skills/gate/SKILL.md` and `nirvana/claude/skills/seat/SKILL.md`.

## Discrepancies and Rulings ("The plan was wrong here")

1. **`tests/nirvana_plugin_hooks.rs` hardcoded hook counts**:
   `tests/nirvana_plugin_hooks.rs` asserted that exactly 9 hooks and 5 event names were declared (frozen in Plan 13 when hook count grew from 7 to 9). Registering `log-usage`, `prompt-baseline`, `guard-edit`, and `check-edit` (which adds `PostToolUse` as a 6th event name) increased the total declared hooks to 14. Following the precedent established in Plan 13, `tests/nirvana_plugin_hooks.rs` was updated to include `"PostToolUse"` and assert `ran == 14`.
