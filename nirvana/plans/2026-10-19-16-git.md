## 1. What exists (read 2026-10-19)

- **Old Nirvana's card** (`Nirvana/plugins/git-widget/plugin.py`, `ui/git-card.js`):
  - One `git status --porcelain=v2 --branch` per poll gives the branch, the upstream, ahead and behind, the changed count
    and the first files.
  - **Pull** runs `git pull --ff-only <remote> <branch>`. **Push** runs `git push <remote> <branch>`. Both remote and
    branch come from the repo's own `# branch.upstream`, never from the caller.
  - Each press is refused before anything runs when the branch is no longer the one the card showed (`expect_branch`),
    when there is no upstream, or when the upstream does not read as `<remote>/<branch>`.
  - Each press first asks "Pull 2 commits from origin into main?" with the changed count, and acts only on a second press.
  - After a press the row is read again rather than patched, and git's own words are shown.
- **herdr already reads git per space.** The sidebar shows the branch and ↑/↓ (`src/ui/sidebar/tokens.rs`,
  `src/app/git_refresh.rs`). It has no changed files, no Pull or Push, and no CI.
- **The Jobs square** (`src/client/shell/nirvana_jobs.rs`) is the pattern to copy: the focused agent's `cwd` is the
  folder, a poll off the draw path fills a cache, and a panel opens on click, with one panel open at a time.

## 2. The Git square

- **It reads the focused space's folder**, the same way `jobs_tab` does.
- **The label** reads, for example, `main ↑1 ↓2 · 3 changed`.
  - A count that is 0 is left out, so a clean, level branch reads `main`.
  - A CI state from §4 adds one mark at the end: `✓` passed, `✗` failed, `●` running.
  - Narrow, it drops the word "changed" and keeps the numbers.
  - Outside a git repo, the square is not drawn.
- **The draw path reads nothing.** A poll runs `git status --porcelain=v2 --branch` every 5 s while the panel is open and
  every 15 s otherwise, as the other squares do. It caches the result per folder.
  - Every git and gh child gets `CREATE_NO_WINDOW` on Windows, and a timeout of 10 s for status and 60 s for network
    commands.

## 3. The panel

- **Rows:** the title `Git · <folder>`, then `branch <b> → <upstream>` (or "no upstream"), then
  `↑N ahead  ↓M behind (last fetch)`, then the changed count and up to 8 paths. A rename shows its new path.
- **Buttons:** `[Pull ↓M]`, `[Push ↑N]` and `[Fetch]`.
  - **Pull** is disabled with no upstream. **Push** is disabled with no upstream or nothing ahead. **Fetch** is disabled
    with no upstream. A disabled button says why on the status line when clicked.
  - **The first press asks.** For example: `Pull 2 commits from origin into main? 3 changed files in the tree.
    [Pull] [Cancel]`. Only the second press acts. Esc or Cancel drops it. Fetch does not ask, because it changes no
    files.
  - **The rules are the old card's, unchanged.** Pull is `git pull --ff-only <remote> <branch>`. Push is
    `git push <remote> <branch>`, with no force, no lease, no delete and no refspec. Fetch is `git fetch <remote>`.
    Remote and branch come from `# branch.upstream`. Just before acting, status is read again, and the press is
    refused, with nothing run, if the branch differs from the one the panel showed.
  - **It runs off the draw path** with `GIT_TERMINAL_PROMPT=0`, so a missing credential fails instead of hanging. The
    button reads `Pulling…` meanwhile.
  - **Afterwards,** the row is read again and git's own first lines are shown on the status line: the failure text, or
    the summary on success.
- **Keys:** the arrow keys move between buttons, Enter presses, and Esc closes, as the Jobs panel does.

## 4. The CI line

- **It is shown only when** `gh` is on PATH, the upstream remote's URL is a github.com URL, and the branch has an
  upstream.
- **The poll:** every 60 s, off the draw path, it runs
  `gh run list --branch <upstream branch> --limit 1 --json status,conclusion,workflowName,createdAt,url`.
  - `status` that is not `completed` reads **running**. Otherwise `conclusion` `success` reads **passed**, and any
    other conclusion reads **failed**, with the conclusion word shown.
  - No run, or a gh failure such as signed out, means no CI line and no mark. The gh text is never shown on the square.
- **The panel row** reads `CI  <workflow>  passed  12m ago`.
- **It reads only.** Nothing runs `gh pr`, `gh run rerun` or any gh write.
  - The probe sets `BROWSER` and `GH_BROWSER` to a program that opens nothing, and `GH_PROMPT_DISABLED=1`, so gh can
    never start a sign-in (CLAUDE.md rule 15).

## 5. Verification

- **Unit tests** cover:
  - the porcelain parse on recorded text: a clean tree, dirty files, a rename, untracked files, a detached head, and no
    upstream;
  - the label, both narrow and wide;
  - the button states;
  - the `expect_branch` refusal;
  - the CI parse on recorded JSON: running, passed, failed, an empty list, and invalid JSON.
- **Tests on real git:** a temp repo with a temp bare remote.
  - Push one commit; the row then reads ↑0.
  - A second clone pushes a commit; Fetch then reads ↓1, and Pull fast-forwards it.
  - A diverged branch: Pull is refused by git, and the local commit is untouched.
  - No test touches a repo outside its temp dir, the owner's remotes, or the network.
- **Live:** in an isolated herdr server, on the same scratch repo pair, `herdr pane read` or a client snapshot shows the
  square's label.
- **Every assertion gets a control** in `nirvana/controls.d/p16.py`.

## 6. Not in this version

- **No pull requests**: no listing, opening or review state (L3 left them out).
- **No branch switching, commit, stash or discard.** The panel never edits the tree beyond a fast-forward pull.
- **No repo picker.** The square follows the focused space.
