## 2. The rule every package keeps: no machine starts without the owner

- A batch never contains a step that starts a print, a laser job, or a send to a device. A batch that names one is
  refused whole, before any step runs.
- The existing human gates stay exactly as they are:
  - xtool's `safety.py` and `job_start`;
  - `beta_send_print`'s `confirm`.
- No package adds a way around them.
- Only the gated tool itself may click a send or start control. A guard refuses such a click, by its label, from
  every other path, the batch included.

## 3. P29a: Bambu, in the 3D-Printer Flow repo

- **Worktree:** `C:\Users\fahim\Desktop\Pojects\3D-Printer-Flow-gui29`.
- **Branch:** `feat/gui-tools-29`, from `feature/bambu-mcp-2.08-smart-detail`.
- **Commit 1** imports the owner's untracked `tools/studio-gui-mcp` exactly as it is, leaving out `shots/`,
  `__pycache__` and `.venv`. The owner's checkout is never edited.

1. **`beta_run(steps)`** is the batch.
   - It takes a list of `{action, args, expect}`.
   - It runs the steps in one process and stops at the first step whose `expect` fails.
   - It returns per-step ok/why, the final `beta_state`, and one optional crop.
   - The same runner is a CLI: `python -m studio_gui_mcp run steps.json`. One process serves a Bash-only seat.
2. **`beta_state`** returns structured text:
   - the foreground window and Studio's own window;
   - the active tab, read from more than one source, with disagreement reported as `unsure` rather than picked;
   - open dialogs, by title;
   - the named field values asked for.
3. **Screenshots:**
   - `beta_screenshot(region=...)` crops to a named area (preview, settings panel, dialog) or to a box.
   - The full image is kept as a fallback.
   - Each file gets a unique name. An unchanged image (same hash as the last one) is reported as unchanged, not
     re-sent.
4. **Guards:**
   - Before any key or click, `prep()` brings Studio to the front and checks the foreground window. A mismatch
     refuses the step.
   - After a state-changing step, the value is read back. A read-back that disagrees fails the step.
   - File dialogs get a timeout. A timed-out dialog is closed, and the step fails with its title.
5. **Small fixes:**
   - `get_printer_status` in `vendor/bambu-printer-mcp` gets a `fields=` filter and a short default summary.
   - `curr_bed_type` is rejected as `wrong_family` through `settings.set_print`: find why and fix it, or report it.

Tests run on stand-ins: a fake window list and fake readers. **No test or builder run starts Bambu Studio, clicks in
it, or talks to a printer.**

## 5. P29c: workers can reach the servers (Nirvana-Herdr)

- **Worktree:** `C:\Users\fahim\Desktop\Pojects\Nirvana-Herdr-p29`.
- **Branch:** `p29-gui-tools`.

1. An order whose `needs` names a server in the project's `.mcp.json` gets a per-order `--mcp-config`.
   - The `--mcp-config` holds only those servers, copied from the project's definition. `--strict-mcp-config`
     stays, so nothing else loads.
   - The server names are matched exactly.
   - The order also gets `--allowedTools` for those servers' tools, `mcp__<server>__*`.
2. A `needs` naming `bambu-studio-beta` or `xtool` on an agy or gemini seat:
   - the seat pick skips that seat, because agy panes cannot see the Studio window (§1);
   - if no Claude seat is free, the order is refused, with the reason.
3. The worker brief for such an order gets one line: "Use the `*_run` batch and `*_state`; read crops, not full
   screenshots; never start a print or a job."
4. Any error building the config keeps today's argv and logs one line.
   - **Changed at the review round (2026-10-27):** an order seated for a server it cannot get at launch does not
     start; it fails with a reason naming the server. Running without it would send the worker back to Bash and
     pywinauto, the jig-print run's path. Record `nirvana/plans/2026-10-26-29-records/p29c.md`.
