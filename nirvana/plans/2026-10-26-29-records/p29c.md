## Decisions the plan did not make

- **Every server need is Claude-only, not only the two desktop servers.** §5.2 names `bambu-studio-beta` and
  `xtool`. But only the claude argv carries `--mcp-config`: an agy worker seated for `needs: bambu` would start without
  the server it was seated for. A desktop server's reason names the window; any other names the flag.
- **A capability wins over a server of the same name.** No seat capability today shares a name with a server in the
  3D-Printer Flow `.mcp.json`, so nothing seats differently; the rule keeps it that way if one ever does.
- **The definition goes in a file, never on the command line.** The project's `.mcp.json` holds a printer token in
  `env` for `bambu` and `bambu-studio`, and the journal's `started` event records the argv.

### Decisions this round made

- **"Seated for a server" at launch is a need no seat has as a capability.** The journal's `Seated` keeps the raw
  needs, and at seat time the unknown-word check refused every such need that named no server, so each one left names a
  server. No journal field was added.
- **seats.toml refused at launch** keeps going: the needs `.mcp.json` names are read as the servers, with one line. If
  `.mcp.json` cannot be read too, the order fails. Plan §5.4's "any error keeps today's argv" is otherwise gone: F3
  overrides it.
- **A broken `.mcp.json` at the reseat** reads as no seat, so the order defers or asks by today's rule; the Ask's
  question carries `rate_decision`'s reason, not the file's. At the send-back the Ask names the file.
- **Windows permissions are not built.** `std` has no ACL call; narrowing the file means the Win32 security API. The
  file takes the ACL of the project folder (the owner's profile).
