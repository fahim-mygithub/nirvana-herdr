## 1. What exists (read 2026-10-19)

- **Claude Code writes a background Bash command's output to a task file.** The path is
  `%TEMP%\claude\<encoded cwd>\<session>\tasks\<id>.output`, and `[exited with code N]` is appended when the command
  ends.
- **Commands that write their own log leave that task file empty.** The orchestrator's gate runs redirect to a log file
  in the scratchpad, for example, so for exactly the long runs the owner wants to watch, the task files show nothing.
- **herdr already opens worker panes** (plan 12 O3, `nirvana_worker::open_pane`).
- **The mod strip holds squares** (Preload, Running, Memory, Seats; `src/client/shell/nirvana_mods.rs`).

## 2. `herdr job`

- **`herdr job run --name <name> [--cwd <dir>] [--wait] -- <command...>`**
  - It creates `<home>/nirvana/jobs/<id>/job.json` with `id`, `name`, `argv`, `cwd`, `space`, `pane`, `started`,
    `ended` and `exit`.
  - It opens a pane in the space's **Jobs tab**, creating the tab when the space has none, and focuses the new pane
    within that tab. The owner's working tab is never switched away from.
  - The pane runs `herdr job exec <id>`. That starts the command with its output piped, and copies every line both to
    the pane and to `<id>/out.log`. When the command ends, it writes `ended` and `exit` to `job.json`.
  - `run` prints the id and returns. With `--wait`, it blocks until the job ends, then prints the last 20 lines and
    exits with the job's code.
  - Outside herdr, with no server, `run` runs the command in place with the same log and record, so a script never
    breaks.
- **`herdr job list`** shows each job's id, name, state (running, passed, failed or lost), elapsed time and last line.
  - "lost" means the exec's process is gone and no exit was ever written.
- **`herdr job status <id>`** prints one job's line.
- **`herdr job tail <id> [-n N]`** prints the last N lines of its log, 20 by default.
- **`herdr job stop <id>`** ends that job's process tree only, never any other process.
- **`herdr job clean`** removes jobs that ended over 7 days ago.
- **A finished job's pane stays** until the owner closes it. Its last line reads `[job <name>: exit N after Xs]`.

## 3. Claude Code's own background tasks

The Jobs square also lists the task files of Claude sessions in the space's folder:
- **Which files:** the newest 10, modified in the last 12 hours, under `%TEMP%\claude\<encoded folder>\*\tasks\`. Use
  Claude Code's encoding, where each character that is not an ASCII letter or digit becomes `-`.
- **State:** running until `[exited with code N]` appears, then passed (0) or failed. A file not touched for 24 hours
  with no exit line reads "unknown".
- **They are read only and have no pane.** A click opens a pane in the Jobs tab that tails the file.

## 4. The Jobs square

- **The label** reads, for example, "Jobs 2 running · 1 failed". With nothing in the last 12 hours it reads "Jobs".
- **The panel** lists jobs and then Claude's tasks, newest first. Each row shows the name, the state, the elapsed time
  and the last line, cut to the width.
- **A click on a job** focuses its pane in the Jobs tab.
- **The draw path reads nothing.** A poll off the draw path refreshes the list every 2 s while any job runs and every
  15 s otherwise, as the other squares do.

## 5. Agents use it

- **`nirvana/claude/ROLE.md`** gains one line: "run builds, test suites and gates longer than about a minute with

## 6. Verification

- **Live:** an isolated herdr server and a scratch home.

  - A second job lands in the same Jobs tab.
