## 1. Measured 2026-10-21

- **Why two windows mirror.** herdr keeps one current space per session, on the server: `AppState.active`
  (`src/app/state.rs`), changed by `switch_workspace` (`src/app/actions.rs`). Every client attached to the `nirvana`
  session draws that one space, so a second window shows what the first shows.
- **Why there is a second window.** The verb (`nirvana/windows_shell.py` `verb_command`) runs `wt -w new -p Nirvana
  -d "%1" herdr.exe --session nirvana nirvana window "%1"`. `-w new` always makes a window. `herdr nirvana window`
  (`src/nirvana_launch.rs` `window`) then opens or focuses the folder's space through the `OPEN_COMMAND` command
  (`src/app/nirvana_new.rs` `nirvana_open_folder`), claims the window's taskbar identity per folder
  (`src/nirvana_taskbar.rs` `claim_window`, app id `Nirvana.Herdr.<folder hash>`), toasts, and runs the client.
- **The parts that exist:** the server tracks the outer terminal's focus (`AppState.outer_terminal_focus`); panes
  carry a `seen` flag that the sidebar draws as the unseen accent; `release_window` clears the taskbar identity on
  exit.
- **The crate has one binary,** `src/main.rs`, and no library target. `install.py` builds with `cargo build --release
  --locked` and copies `herdr.exe` alone.

## 2. The launcher

- **A second binary, `nirvana-open.exe`,** from `src/bin/nirvana-open.rs`, built with `#![windows_subsystem =
  "windows"]` so Explorer shows no console. Std only.
- **It runs** `herdr.exe --session nirvana nirvana open <folder>` from its own folder, with `CREATE_NO_WINDOW`, and
  exits. With no folder it runs `herdr.exe --session nirvana nirvana open`.
- **The verb's command** becomes `"<home>\bin\nirvana-open.exe" "%1"` (and `"%V"` for the background verb).
  `verb_command` and its Python tests change with it.
- **`install.py`** copies `nirvana-open.exe` beside `herdr.exe`, with the same rename-if-running step.

## 3. `herdr nirvana open [<folder>]`

### 3.1 The window mark

- **The verb's window writes a mark** at `<home>/nirvana/window.json` once it has claimed its taskbar identity:
  `{"pid": <herdr client pid>, "hwnd": <Terminal window handle>, "at": <unix seconds>}`. It writes with `write_bytes`
  semantics: one write of the whole file.
- **On exit it removes the mark** only when the mark's pid is its own.
- **A mark is live** only when all three hold: the process at `pid` runs and its image is `herdr.exe`; `IsWindow(hwnd)`
  is true; the session's server is listening. A pid file alone is not liveness; this repo measured that.
- **The check is a pure function** over those three facts, so it is unit tested without a real window.

### 3.2 The route

| A live mark? | A folder? | What happens |
|---|---|---|
| yes | yes | invoke `OPEN_COMMAND` for the folder: it focuses the folder's Nirvana space or opens one; mark the space new (§4); flash the window (§5); toast as today |
| yes | no | flash the window |
| no | yes | start a window as the verb does today: `wt.exe -w new -p Nirvana -d <folder> herdr.exe --session nirvana nirvana window <folder>` |
| no | no | start a window on the session with no folder: `wt.exe -w new -p Nirvana herdr.exe --session nirvana nirvana window` |

- **`herdr nirvana window <folder>`** takes the first row's path itself when a live mark exists and the mark is not its
  own: it invokes the open, marks the space new, flashes the live window, and exits 0. Old per-folder pins and any
  `wt` command line still route into the one window this way; their Terminal window opens and closes.
- **`herdr nirvana window` with no folder** starts the server in the user's home folder if it is not running, claims
  the window, writes the mark and runs the client on the spaces that exist.
- **Errors go to a file.** The launcher has no console, so `nirvana open` appends one line per failure to
  `<home>/nirvana/open.log` and falls through to starting a window.
- **Two clicks at once** may both see no live mark and make two windows. Not handled; listed in §6.

## 4. The new space is highlighted until visited

- **When the open comes from a live window that is not focused** (`outer_terminal_focus == Some(false)`), the space
  it opened or focused has its root pane marked unseen, so the sidebar draws the existing unseen accent on it.
- **The space still becomes the current one,** as `nirvana_open_folder` does today. The owner just clicked in
  Explorer, so no keystrokes go to Nirvana at that moment.
- **The accent clears** the way unseen panes clear today: when the window regains focus on that space.
- **The open command carries this** as a flag in the command id, the way `OPEN_FRESH` is carried
  (`open_command_id`, `parse_open_command`).

## 5. The taskbar

- **The flash:** `FlashWindowEx` on the mark's window handle with `FLASHW_TRAY | FLASHW_TIMERNOFG`, so the button
  flashes until the window comes to the front. The window is not brought forward.
- **One identity for the window:** app id `Nirvana.Herdr.Window`, display name `Nirvana`, the mark icon, and the
  relaunch command `"<home>\bin\nirvana-open.exe"`, which focuses or opens the one window. `Identity::for_folder` is
  replaced by an identity that names no folder.
- **The letter badge follows the current space.** The client that claimed the window re-sets the overlay when the
  current space's folder letter changes. A space with no folder keeps the last letter.
- **The "new" menu's Nirvana entry** (`claim_menu_window`) claims with the same identity.
- **The toast** stays as it is: "Nirvana · <folder>".

## 6. Not in this plan

- **Two clicks within the same second** may make two windows (§3.2).
- **Old per-folder pins** keep their own app id, so they open their folder into the one window but do not show as
  running. The owner re-pins once.
- **Bringing the window to the front.** The owner asked for a flash.
- **Other platforms.** The launcher and the flash are Windows only; elsewhere `nirvana open` routes and does not
  flash.

## 7. Verification

- **Unit tests:**
  - The liveness check: each of the three facts false alone gives not live; all true gives live.
  - The route table: all four rows, from fixed liveness and folder inputs, as data (no process started).
  - The mark: write, read back, remove only by its own pid; a torn or empty file reads as no mark.
  - `parse_open_command` and `open_command_id` round-trip the new-space flag with and without `OPEN_FRESH`.
  - The open with the flag while `outer_terminal_focus == Some(false)` leaves the space's root pane unseen; with focus
    `Some(true)` it is seen.
  - The window identity names no folder and its relaunch command names `nirvana-open.exe`.
  - The badge letter follows the current space's folder.
- **Python tests:** `verb_command` names `nirvana-open.exe` and the folder token; `install.py` copies both binaries
  (test against a scratch root).
- **No test** starts Windows Terminal, flashes a real window, reads the real install home, `~/.claude` or `~/.gemini`.
- **Controls:** every assertion gets a sabotage control in `nirvana/controls.d/p21.py`.
- **After the install, by the orchestrator,** one live check with the owner's go-ahead, since it opens a window on the
  owner's desktop: open one folder, then a second; count Terminal windows with the Nirvana id (expect one) and read the
