## What was built

The review round below changes the gate (it no longer forgets on a yes), lands both hunks, and widens the
sparkle to the narrow and machines sidebars; this section is the first build as it was.


- `src/nirvana_spaces.rs`: the frames `✧ ✦ ✶ ✷ ✸ ✷ ✶ ✦` (`SPARKLE_FRAMES`), 250 ms a frame (`SPARKLE_FRAME`), the
  fallback `◐`, one window-wide clock (`sparkle_frame`), and the repaint gate: the spaces list notes the frame it drew
  when a drawn space sparkled (`note_sparkle_drawn`), and `take_sparkle_due` answers yes only when that is so and the
  clock has moved to another frame. A yes forgets the drawing, so a repaint that draws no working space (the worker
  ended, the list hidden or scrolled) stops the repaints.
- `src/client/shell/nirvana_spaces.rs`: `space_working` (any agent of the space Working or Blocked, or a live worker
  row the list already read this frame; a folded worktree parent counts its hidden linked children's agents, as
  herdr's `displayed_workspace_status` does) and `space_marker` (sparkle in the working colour, Blocked keeps `×`,
  anything else today's marker). The tests are the `sparkle_tests` module at the end of this file.
- `src/client/shell/sidebar.rs`: `render_sidebar` reads one frame per list and passes the marker to a new
  `render_workspace_rows_with_marker`; `render_workspace_rows` keeps its signature for the endpoint sidebar and calls
  it with today's marker.

## Measurements

- Which agents fed the space marker before: the server's `Workspace::aggregate_state` (`src/workspace/aggregate.rs`)
  over the space's panes only, priority Blocked 4, Idle-unseen (Done) 3, Working 2. Seated workers that run off the
  space's panes (the live rows `space_workers` reads from the subagents cache) never fed it. Both causes of the
  owner's screenshot are real: Done outranks Working, and a seat worker is not a pane of the space.
- The client shows Done only for an agent it saw working (`endpoint_agent_state::projected_status`); the tests feed
  a Working snapshot before the Done one, or the space reads `○`.
- Width: `unicode-width` 0.2.2 (the crate the sidebar's `put_text` and `fit` use) gives 1 for all eight frames
  (`every_frame_is_one_cell_wide`); none falls back to `◐`. Not measured: the glyphs as drawn by JetBrains Mono in
  Windows Terminal.
- Repaints: the window's timer ticks every 100 ms (`ClientShellState::timer_delay`); with the tick line below, a
  working list repaints at most once per new frame (about 4 a second, as 300/200 ms steps on the 100 ms tick) and a
  list with nothing working adds none. The encoder (`blit_encoder.encode`) writes only cells that changed, so a
  sparkle repaint writes the marker cells (plus anything else that changed).

### Found in the build, not in the review

The build's tests never drew the real window. `compose_at` installed a pane surface of projection revision 1 over a
snapshot of revision 2; `set_pane_surface` drops a surface older than its snapshot, so `compose` took
`compose_unavailable`, the placeholder that draws the spaces list in place of the whole window, with
`sidebar_collapsed: false` whatever the state said. The tests passed, but `render_shell` and its sidebar branches were
never reached. `state_for` now gives the surface the snapshot's revision and asserts the surface is installed. With
the real window, a Done agent whose pane is on the surface reads as seen (Idle, `○`, by
`endpoint_agent_state::acknowledge_surface`), so the test surface's one pane is `pane_shown`, which no test agent is in.

### Measurements and statements

- Start latency, a worker counted through its own pane (an agent of the space): the next snapshot, then the next
  frame (at most 250 ms). A seat worker counted only through its row: its row appears when the subagents poller next
  reads the orchestrator pane's journals, every 10 s while that pane's view has no running row and every 2 s while it
  has one (`poll_with`, `reread_interval`); so up to about 10 s after the `Seated` event, plus the read, plus one frame.
- Stop latency: the parent's view has a running row, so it is re-read every 2 s; the row leaves (or turns waiting) on
  the first read after the journal says so, and the next drawing settles the marker: up to about 2 s plus the read.
  The same holds for Running to Asked or Deferred.
- A headless worker whose process died without a journal event still sparkles: its `target_pane_id` is the
  orchestrator pane, which is there. Catching it needs a liveness read (a pid, a stream's age) that the sidebar does
  not make; not done.
- Cost: each sparkle frame is a full `compose` of the window (every laid-out space's workers read from the cache,
  `ask_subagents` per agent, the hit map rebuilt) at 4 Hz, also in a window in the background or over a remote
  connection. Only the cells that changed are written (`blit_encoder.encode`), so the bytes are the marker cells; the
  work is not. The boundary-timed tick adds at most one timer wake per frame (about 14 wakes a second while
  sparkling, against 10); with nothing sparkling the timer waits its 100 ms default and nothing more. Not measured
  with a profiler.
- The narrow and machines lists now ask the worker cache for this machine's spaces (`ask_subagents`), as the spaces
  list does; that keeps those panes polled while the narrow sidebar shows. No read happens on the draw path.
