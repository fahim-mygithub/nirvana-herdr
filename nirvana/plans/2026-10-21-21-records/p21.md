## What was built

1. **Step 1 (§3.1): The mark and liveness check**
   - Added `WindowMark { pid, hwnd, at }` written to `<home>/nirvana/window.json` on claiming window property.
   - Added pure `liveness_check(pid, hwnd, session, process_checker, window_checker, server_checker)` requiring all three facts:
     - The process at `pid` runs and is `herdr`
     - `IsWindow(hwnd)` returns true
     - The session server is listening
   - Added `remove_window_mark_if_own_pid` on window cleanup.
   - Unit tests for all three facts, torn/empty mark files, and pid matching in `src/nirvana_launch/tests.rs`.

2. **Step 2 (§3.2): The route**
   - Implemented `OpenRoute` enum and `route_open` mapping all 4 states of `(live_mark, folder)`:
     - `(Some(mark), Some(folder))` -> `FocusOrOpenFolder { folder, hwnd: mark.hwnd }`
     - `(Some(mark), None)` -> `FlashWindow { hwnd: mark.hwnd }`
     - `(None, Some(folder))` -> `StartWindowFolder { folder }`
     - `(None, None))` -> `StartWindowNoFolder`
   - Implemented `spawn_window` starting a new window via `wt.exe`.
   - Implemented `flash_window` via `FlashWindowEx(FLASHW_TRAY | FLASHW_TIMERNOFG)`.
   - Implemented `open` subcommand: CLI `herdr nirvana open [<folder>]` routing clicks without a console window, logging errors to `<home>/nirvana/open.log` in append mode.
   - Unit tests covering route table and log appending in `src/nirvana_launch/tests.rs`.

3. **Step 3 (§4): The highlight**
   - Updated `OPEN_COMMAND` payload with `OPEN_NEW: &str = "new"`.
   - Updated `open_command_id` and `parse_open_command` in `src/nirvana_launch.rs` to round-trip `fresh` and `new_space` flags.
   - In `src/app/nirvana_new.rs`, if a new space is created and `self.state.outer_terminal_focus == Some(false)`, mark the root pane `pane.seen = false` so it renders with the orange unseen badge (`[o]`) until focused.
   - Unit tests covering command serialization and unfocused space creation in `src/nirvana_launch/tests.rs` and `src/app/nirvana_new.rs`.

4. **Step 4 (§5): The taskbar**
   - Replaced `Identity::for_folder` with unified `Identity::window(home, herdr, letter)`.
   - Single application ID `Nirvana.Herdr.Window`, display name `Nirvana`, and relaunch command `"<home>\bin\nirvana-open.exe"`.
   - Added `set_badge(letter: Option<char>)` dynamically updating the overlay icon as the active space switches.
   - Integrated `update_taskbar_badge` in `ClientShellState::apply_snapshot` when the active workspace changes.
   - Unit tests in `src/nirvana_taskbar/tests.rs`.

5. **Step 5 (§2): The launcher and install**
   - Added standalone Windows subsystem binary `nirvana-open` in `src/bin/nirvana-open.rs` (`#![windows_subsystem = "windows"]`, std only) that spawns `herdr.exe --session nirvana nirvana open [<folder>]` with `CREATE_NO_WINDOW`.
   - Added `[[bin]]` entries in `Cargo.toml`.
   - Updated `verb_command` and `install_verb` in `nirvana/windows_shell.py` to use `nirvana-open.exe`.
   - Updated `install.py` to copy both `herdr.exe` and `nirvana-open.exe` into `<home>\bin\` using rename-if-running logic.
   - Unit tests in `src/bin/nirvana-open.rs`, `nirvana/test_windows_shell.py`, and `nirvana/test_scripts.py`.

## Review fix (orchestrator, 2026-10-21)

- **A window renamed by an install read as dead.** `install.py` renames the running `herdr.exe` to
  `herdr.old-<stamp>-<pid>.exe`, and `is_herdr_process` accepted `herdr.exe` alone, so after every install the next
  "Open Nirvana" made a second window. `is_herdr_image` takes both names. Test
  `a_window_renamed_by_an_install_still_runs_herdr`, control `p21_mark_renamed_install_image`.
- **The badge could not follow the space in a window opened with no folder.** The client runs as a child of
  `herdr nirvana window` (`supervise_code`), so the window process's claim is invisible to it, and the client's
  `is_window_claimed` read `NIRVANA_WINDOW_FOLDER`, which a window with no folder never sets. The window now sets
  `NIRVANA_WINDOW_CLAIMED` after a claim, and the menu's claim skips when it is set.
- **The badge test was hollow.** It set overlays on the recorder by hand, and its control sabotaged the test's own
  line. The letter is now picked by `space_badge_letter`, tested on a fixed pane list; the control sabotages it.
- **`herdr nirvana open` takes a relative folder** and makes it absolute, since the open command refuses a relative
  one.
- **The CHANGELOG entry was rewritten.** It named `FLASHW_ALL` and an id `Nirvana.Herdr.WindowClaimed` the code does
  not use, and said the old build opened a duplicate space on an open folder, which it did not.
- **Not covered by a test:** setting `NIRVANA_WINDOW_CLAIMED` in `window`, and whether a starting Nirvana Claude goes
  through a working state that marks its pane seen before the owner looks. The live check reads the sidebar for it.
- **Gate after the fix:** fmt 0; clippy clean; nextest 4065 run, 4064 passed, 1 failed (the known
  `windows_plugin_pane_commands_resolve_from_plugin_root_with_cwd_override`), 30.7 s; unittest OK; dry run 1130 of
  1130; 18 `p21_` controls, 0 bad.
