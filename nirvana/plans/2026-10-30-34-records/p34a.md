## Where the plan was wrong, or silent

1. **`k` opens `knowledge/`.** `k` is the Preload panel's up key (`j`/`k`, `nirvana_mods.rs`). Built as `K`; `k` still
   moves up (the panel test presses both).
2. **"opens `knowledge/` in an edit tab".** The edit tab takes a markdown file (`editable_file`); no terminal editor
   herdr starts opens a folder. Built: a new command `nirvana.edit_dir:` runs the editor with no file in a tab whose
   folder is `knowledge/`, so its open dialog lists the cards. Not seen live.
3. **The card slug.** The staged set's longest file name is 50 characters; `nirvana_lessons::slug` cuts at 48. A
   card's file stem may be up to 64 of `[a-z0-9-]`; a card a teacher makes takes `slug(name)`, which fits.
4. **The ledger.** "Reuse plan 33's ledger" cannot be literal: `lessons/ledger.jsonl` rows carry lesson index entries
   and `rollback` restores lessons. Cards have their own `knowledge/ledger.jsonl` with the card's text before and
   after, the same `op-<n>` ids, the same refusals (rolled back already, changed since, a slug that is not a card's).
5. **`effect`, `date` and `tags` in a teacher's op are optional**, as in the card format. `evidence` is not a card key
   (unknown keys are refused), so it goes in the ledger row, redacted, never in the card.
6. **Who starts teaching.** herdr cannot tell the owner from Nirvana Claude except by the shell's environment. A shell
   whose `nirvana_jev::caller()` names an agent (Claude Code's `CLAUDECODE`, agy's, Codex's) must give `--quote`,
   checked against Nirvana Claude's recorded session as `--send-ok` is; a terminal with none of those is taken as the
   owner. A worker's shell is an agent's too, so it needs a quote in the owner's prompts, as plan 31's rule does.
7. **The teaching order is gated by herdr.** The plan does not say who gates it. `seat exec` gates a `done` teaching
   order itself (its ops are checked deterministically, as a review's are) and still wakes Nirvana Claude to report;
   a `needs_answer` one is left to the orchestrator, which gates it with `herdr gate run`, applying nothing.
8. **A teaching order is seated in the project root**, as `seat run` seats any order without a worktree, with the
   profile applied (so a reel teacher has the reel tools to measure with). It is held, as a review is, by the gate's
   folder check, not by a tool filter: a teacher may write project files; it cannot add a card around herdr.
9. **The run copy and `copy_into_run`** needed no change: `load` now reads the resolved `profile.md`, whose bytes are
   copied.

  and `herdr kb search --profile reel-editor closer` found none. After `herdr profile check reel-editor --adopt`
  (`adopted 40 cards`), the check prints `reel-editor: ok (40 cards)`, exit 0, and the search lists the cards. The
  staged folder's sha256 list (41 files) was identical before and after.
- **Controls.** 104 `p34a_` controls (58 kept, 46 new; `p34a_snap_counts_index` removed, since cards no longer use
  `nirvana_lessons::folder_snap_in`), each run alone: 104 reddened their test. The eight older controls `touched.py`
  lists against master all reddened.
- **Tests.** 4444 run, 4443 passed; the one failure is

### Not done, or not proven

- The lock around `write_snap` and `held_back` (S4) has no test: a second handle on the lock in one process blocks
  rather than fails, so a race is not reproduced. Likewise a lock *error* in `offer` (it blocks on contention).
- `herdr profile check --adopt`'s routing in `nirvana_profiles::cli` is shown by the run above, not by a test
  (`cli` ends in `process::exit`).
- `--adopt` has no owner check: a worker with a shell in the project root can run it, as it can edit `index.json`.
  Only orders that read untrusted input (teachers, reviewers) are snapshotted; a plain profiled worker is trusted
  with the project's files as before.
- An agy lesson reviewer still has no tool filter (plan 33's choice); B1's put-back is its only hold on the profile
  folder, and only for writes in that folder.
- A teaching order that never delivers (`failed`, `stopped`) is not gated, so nothing is put back; a card it wrote
  is unknown, never offered, and `profile check` names it.
- `--add-dir <root>` lets a claude teacher read every project file its profile's tools do not deny, `.env` included;
  the order did not forbid it and the method needs the project's measurements. Not seen live.
