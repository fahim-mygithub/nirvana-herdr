## 2. The orchestrator's usage reaches the journal

- **A new `herdr nirvana log-usage`** goes in `hooks.json`'s Stop list, after `jev compact`. It is also called on
  SessionStart with `source` `resume`, to catch a previous session's tail.
- **It skips** when the hook input has `agent_id`, as `stop_cli` does, and when `NIRVANA_ORCHESTRATOR` is not `1`.
- **It reads the transcript.** It takes `transcript_path` from the hook input, the way `nirvana_jev_compact.rs` and
  `nirvana_session_record.rs` do. It sums `message.usage` over assistant lines past a stored byte offset, counting each
  `message.id` once.
- **The offset is stored per session id** in the seat folder and written after the append, so a crash re-reads a
  tail rather than skipping one.
- **The delta goes to the project's most recently started open run** as `Kind::Usage { order: None, attempt: 0,
  session, tokens }` through `Journal::transact`. With no open run, nothing is appended and the offset still moves on.
- **The receipt** prints the orchestrator's tokens in place of "missing" when there is at least one event.

Tests:
- A fixture transcript with 3 assistant lines, one `message.id` repeated: two calls add the de-duplicated sum once.
- An `agent_id` input appends nothing.
- With no open run nothing is appended.
- The receipt shows the tokens.

## 3. Nirvana Claude's own edits have a limit

- **The limit:** across one owner prompt, Nirvana Claude may change at most **1 file and 30 lines** in the project
  outside an order.
  - Lines means added plus removed, as `git diff --numstat` counts them. Untracked files count by their line count.
- **The baseline is taken at UserPromptSubmit,** by a new step in `herdr nirvana` that the UserPromptSubmit hook already
  calls. It records `git diff --numstat` against HEAD plus the untracked files and their hashes, in the seat folder.
  Changes already present when the owner speaks do not count.
- **PostToolUse on `Edit|Write|MultiEdit|NotebookEdit|Bash`** compares the project's state with the baseline.
  - Past the limit, it returns `decision: block` with this reason: "Nirvana Claude edits at most 1 file and 30 lines
    itself (R2). This change is <n> files, <m> lines. Hand it to a worker: `herdr seat pick --book`, then an order."
  - This catches edits made by Python or shell scripts after the fact.
- **PreToolUse on `Edit|Write|MultiEdit`** denies one call whose own `new_string` or `content` already passes the limit,
  with the same reason.
- **Out of scope for the count:**
  - paths under `.nirvana/` and `.claude/`;
  - the user's memory folder;
  - anything outside the project root;
  - `agent_id` inputs;
  - a cwd inside `.nirvana/worktrees`;
  - changes that a `herdr gate merge` makes, which are commits rather than working-tree changes.
- **The core is a pure function** `edit_budget(baseline, now, limit) -> Option<Reason>`.
- **ROLE.md** states the number and points at the hook.

Tests:
- 1 file and 5 lines passes; 3 files fail; 1 file and 31 lines fails.
- A change made through Bash, with no `file_path`, still fails.
- `.nirvana/` paths do not count.
- A baseline with changes already in it counts only the new ones.
- `agent_id` is skipped.

## 4. A retry keeps its model

- **In `send_back`,** when the parent `Seated` has an `override_reason`, the child's request carries
  `override_seat = (<parent seat>:<parent effort>, <parent reason>)`, and the child's `Seated` carries the same
  `override_reason`.
- **This inherited override is not counted** against `overrides_per_run`.
- **In the worker's rate-limit re-seat,** the override is dropped only when the limit was hit on the override seat's
  own pool, so the rule picks another seat; otherwise it is kept. The journal line names which happened.

Tests:
- A parent with an override and a failing axis gives a child on the parent's seat and effort with the parent's reason.
- The run's override count is unchanged.
- A re-seat after a limit on the override's pool drops it; a limit on another pool keeps it.

## 5. Research is checked

- **The Work Report gains an optional `sources` array** of `{url, used_for}`. The worker brief for classes starting
  `research.` or `media.` requires it.
- **A new gate axis, `sources`,** for those classes:
  - it fails with no sources;
  - it fails for each source URL that does not appear in the order's stream as a fetch, read or browser call;
  - URLs are compared after trimming a trailing `/` and the fragment.
- **`herdr run end` refuses** while an order is delivered and not gated, naming each one. `herdr run end --abandon
  <order> --why <text>` records an `abandoned` verdict for one order so the run can end. A missing verdict is a
  failure (CLAUDE.md rule 8).
- `skills/gate/SKILL.md` says research and media orders are gated like builds.

Tests:
- A cited URL never fetched fails; a fetched URL passes; an empty list fails; a build class without sources is
  unaffected.
- `run end` with a delivered, ungated order exits 2, and `--abandon` lets it end with the verdict journaled.

## 6. A build order names its files

- **`herdr seat run` refuses**, with exit 2, an order of class `build.*`, `fix.*` or `plan` whose `owns:` is empty:
  "a build order needs an `owns:` line naming the files it may change".
- **For those classes, the gate's empty-owns case becomes `Mark::Fail`,** "unbounded: the order names no owned file".
  Every other class keeps the Note.
- `skills/gate/SKILL.md` and the seat skill say a build order must carry `owns:`.

Tests:
- `owned_axis` with empty owns on `build.bounded` fails, and on `research.web` gives a Note.
- `seat run` on a `build.*` order without `owns:` exits 2.
