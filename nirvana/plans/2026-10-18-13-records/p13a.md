## 3. Choices where the plan was silent

1. **The server never computes a preset.** The walk (up to 1 s) and Jev would hold herdr's event loop, so only the
   verb's window process (and `herdr preload apply`) computes; the "new" menu's Nirvana takes the file the folder's
   last open wrote, or the plugin's own.
2. **The catalog is read from `/context` in an empty folder of herdr's own** (`<home>/nirvana/preload/probe`), so a
   project's own skills and CLAUDE.md never enter it; a project's own skill is untagged and stays on. On a machine
   with no reading yet, the first open reads it before Claude starts (a few seconds, once); after that the window
   reads it again in the background when a day old.
3. **Jev tags in the window's background, after Claude started**, at most 6 calls an open; `herdr preload tag
   [--calls n]` does it by hand. The first open of a new machine therefore switches only what the name rules tag.
4. **16 items a tag call**, one choice question each over the tags of `preload.toml`'s `[tags]` plus `none`, one
   shared state. Below the 0.7 floor, `none`, or a tag not offered is written with no tags (asked once, stays on); a
   failed call writes nothing, so its items are asked again.
5. **The tags Jev may answer are `preload.toml`'s `[tags]` table**, with a sentence each; the owner can add one.
6. **herdr never rewrites a catalog line**, it only appends: "owner's edits win" without telling owner lines from
   herdr's. A line whose comment is not `rule` or `jev ...` reads as the owner's.
7. **Core is matched by short name**: a skill's name, an MCP server's plugin (`plugin:context7:context7` is
   `context7`) or connector name, a plugin's id before `@`.
8. **An item off counts only when the last reading listed it**: an uninstalled skill in the catalog is not one of the
   "N off".
9. **The per-turn estimate**: a skill's tokens, a plugin's skills and agents, and for each connected MCP server an even
   share of "MCP server instructions" plus "MCP tools" (`/context` does not split those per server); deferred tool
   schemas count nothing (§1).
10. **"Within 10% share" is ten points of share** (0.10 absolute). Two shares 20 points apart: the first in file order
    wins, whatever its share, as §3.4's "first preset in file order" says.
11. **A choice without an answer (no key, a failure, the wall) is `general` with `retry`**, asked again at the next
    open; Jev's `none` is cached like a rule's choice.
12. **Undo keeps the cached choice**: the record's `preset` is `on` or `off` beside `choice`, so `on` needs no new walk.
    The pins and the undo survive a new fingerprint.
13. **The worker's file holds the switches alone**, not the plugin's settings, whose `env` carries
    `NIRVANA_ORCHESTRATOR=1`. It is looked up by the project's root (`Project::root`), the folder Nirvana opened when
    that is a repository's top.
14. **The resume is refused when another Nirvana Claude already runs on the folder** (two Claudes on one transcript),
    when the session id is not `[A-Za-z0-9-]{1,64}` (it is typed into a shell), and when the record does not parse.
15. **The toast's line goes in its title** after the folder: `show_nirvana_toast` takes no body and the platform file
    is not this package's. The hunk below moves it into the body.
16. **"Fresh Nirvana Claude" is in the "new" menu below Shell** (`NewKind::AFTER_SHELL`): O4a's three and Shell keep
    their places, because `client::shell::tests::keybindings_settings` (not P1's) clicks Shell by its index 3. It is
    named like Nirvana (`nirvana`), so the verb's second click finds it, and it claims the window like Nirvana.
17. **A broken `preload.toml`** is said on the window's stderr and nothing goes off; `herdr preload` exits 2 with the
    parse error.
18. **`herdr preload show` is read only**; `apply`, `off` and `on` write.
