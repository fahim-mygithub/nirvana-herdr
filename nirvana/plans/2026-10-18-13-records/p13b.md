# Plan 13 P2 (p13b) record: the Preload panel's preset, deferred rows and memory row

Built 2026-10-18/19 on branch `p13b-panel` (base `master` after P1 (0.23.0) and P3 merged). Spec: `plans/2026-10-18-13-smart-preload.md` §5 and §8.

## What was built

1. **The header line:**
   - Displays the active preset name, off count, estimated turn saving, and undo hint: `"Preset 3d-print · 31 off · ~5.1k a turn (estimate) · p undo"`.
   - After undo, displays `"Preset off · p on"`.
   - When the folder was never opened (empty preset name), displays `PresetView.reason` (`"no preset yet: Open Nirvana chooses one"`).
   - Formats tokens as per-turn used tokens and deferred tokens separately: `"23.5k a turn · 130k deferred"`. Used total is `Report.total`; deferred total is the sum of report categories whose kind is deferred.
   - Category kinds (`CategoryKind::Used` and `CategoryKind::Deferred`) recorded on `Category` in `Report`.

2. **Deferred rows and provider sums:**
   - An MCP server's tool rows show their tool tokens muted with `"deferred"`, e.g. `"MCP, 46 tools · deferred 19.6k"`.
   - Provider sums count used tokens only, omitting deferred tool schemas.
   - An MCP server's per-turn row is its even share of `"MCP server instructions"` plus `"MCP tools"` (`mcp_server_share`), matching P1 choice 9.

3. **Preset-off rows and pinning:**
   - Rows switched off by the preset are marked with `[p]` in yellow and keep their last observed tokens.
   - Pressing Space on a `[p]` row calls `pin_on(cwd, switch, true)` and pins the row on (`[x]`).
   - Pressing Space on a pinned row calls `pin_on(cwd, switch, false)` and restores it to preset-off (`[p]`).
   - Rows switched off manually in `settings.local.json` keep `[ ]`.

4. **The `p` key:**
   - Pressing `p` calls `set_preset(cwd, !on)` to toggle the preset on or off, refreshing the panel's view and header.

5. **The memory row:**
   - When auto-memory status is over its limit (`status(cwd).over`), the MEMORY.md row shows `"over 4k · t trim"`.
   - Pressing `t` runs `start_trim_propose` off the draw path, then shows `"−0.4k · a accept · x discard"`.
   - Pressing `a` calls `trim_accept(cwd)` to accept the proposal and update the file.
   - Pressing `x` calls `trim_discard(cwd)` to discard the proposal and revert to the over-limit display.
   - Errors display on the row's detail without panicking.

6. **Non-blocking draw path:**
   - `render_panel` and `panel_items` perform no blocking I/O or filesystem reads. `view`, `status`, and trim state are cached in memory and refreshed asynchronously off-thread.

## Two edits outside the package's files

1. **`src/nirvana_preset.rs`:**
   - `PresetView.pinned_on`: The panel needs to know which switches are pinned on over the active preset so it can render them as pinned (`[x]`) and toggle them back off with Space.
   - `Default` for `PresetView`: Provides default initialization where `reason` is `"no preset yet: Open Nirvana chooses one"`, so unrecorded or fresh folders display the correct status text. Also added `Eq` to `PresetView` derives.

2. **`src/nirvana_memory_trim.rs`:**
   - Test trimmer seam (`TEST_TRIMMER` and `set_trimmer_for_test`): Allows unit and integration tests (such as `memory_row_shows_over_limit_proposal_and_responds_to_t_a_x_keys`) to test proposing trims and simulated outcomes without calling the live Jev process.
   - `Eq`: Added `Eq` to `TrimStatus` and `ProposalStatus` derives so they can be held in `View` and compared for structural equality in panel caching.
