## What was built

1. **§2, the rule** (`src/nirvana_idle_compact.rs`). `decide(&Facts) -> Decision` is the one pure function: it
   returns `Send` or `Skip(reason)`, checking in order rule 1 (a rule exists, so the setting is on and valid), rule 2
   (`Agent::Claude`, not a seat worker pane, the process argv read, no `-p`/`--print`), rule 3 (`AgentState::Idle`,
   idle at least `minutes`), rule 7 (not sent in this stretch), rule 4 (the pane's own transcript, last written at
   least `minutes` ago), rule 5 (context at least `min_tokens`) and rule 6 (the owner's last key in the pane older
   than `nirvana_run::OWNER_QUIET_S`, and the strict input line `Empty`). Any unread fact is a skip. Each rule has
   its own test, built from one sending case with that rule alone broken.
   - `context_tokens` sums `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` and leaves out
     `output_tokens`.
   - `read_context_tokens` reads the last assistant line from the transcript's tail, widening 64 KB up to 1 MB
     (`MAX_TAIL`); a last turn further back than that is no reading, so nothing is sent.
   - `choose_transcript` (pure) picks the pane's own transcript; `read_outside` gathers its arguments: the pane
     shell's foreground job and the Claude process in it, Claude's `<config>/sessions/<pid>.json` and that file's
     time, the process start time, the hook's id, the other Claude panes.
2. **§2, the idle time and the stretch** (`IdleStretch`, on `TerminalState::idle_stretch`). Set in
   `recompute_effective_state`, the one place every effective state passes: `Idle` starts a stretch at `now` or
   keeps it; any other state clears it, which also clears "sent" and a pending Enter. A respawned pane's stretch is
   cleared. `next_check_at(minutes)` is a pending Enter's time first; else `since + minutes`, then a minute after
   the last check while the pane is left alone, and `None` once sent or at the cache's hour. Its sums are
   `checked_add`.
3. **§2, the server** (`src/app/nirvana_idle_compact.rs`). `idle_compact_terminals` is the one set of terminals,
   those herdr sees running Claude; `idle_compact_deadline` is their earliest due check and is one of the deadlines
   in `next_headless_loop_deadline_with_git_refresh`, so the server sleeps until then. Each pass of
   `nirvana_idle_compact` handles the one terminal due first:
   - a pending Enter: the line is read again; Enter goes only if it reads exactly `/compact` and the owner has not
     typed since (`enter_gate`); it is sent through `queue_user_input_submission` with no delay and the server waits
     up to 250 ms on the writer's reply; a refused or failed Enter logs one warning and is not tried again;
   - otherwise a check: `checked_at` is stamped first (a terminal with no pane too), then the pane is found, the
     strict input line read from its screen, cursor and scroll, the owner's last key read
     (`nirvana_run::owner_key_at`), the outside facts read, and `decide` called. On `Send` the command is pasted
     (`encode_api_submission_parts`, bracketed paste when the pane asks for it) with `try_send_bytes`; only when
     that queues is the stretch marked sent and its Enter set for 300 ms later. A paste that fails to queue is
     logged and the stretch stays unsent.
   - Log lines: `nirvana: idle Claude pasted /compact` with `pane`, `tokens` and `idle_minutes` (left out when the
     stretch has no start), then `nirvana: idle Claude sent /compact` with `pane`. A skip logs its reason at debug.
4. **§3, the setting** (`src/config/idle_compact.rs`). `[ui.idle_compact]` with `enabled = true`, `minutes = 50`,
   `min_tokens = 50000`. `minutes` outside 1..=59 or a negative `min_tokens` is a config diagnostic, at startup and
   on reload, and the rule is then `None`. `minutes = 59` leaves one check before the cache's hour ends.
   `ConfigEdit::IdleCompact(bool)` writes `[ui.idle_compact] enabled`; a changed setting applies on reload.
5. **§3, the settings section**. `ClientSettingsSection::IdleCompact` ("idle compact"), between Toasts and
   Integrations, with On and Off.
6. **§4.** 112 controls in `nirvana/controls.d/idle_compact.py`. Tests use temporary folders, a thread-local seat
   worker stand-in, stand-ins for the outside reads, and `crate::nirvana::with_test_home` for the server tests; none
   reads a real transcript, a real pane, `~/.claude`, or calls herdr.

## How the input line is decided empty

The reading is `nirvana_idle_compact::read_input_line(screen, cursor, scrolled)`, idle compact's own. It is
stricter than `nirvana_run::prompt_line_text`, which `herdr run wake` keeps using unchanged.

Measured from the screens recorded in a herdr pane from Claude Code 2.1.302 on 2026-10-18
(`src/nirvana_run/fixtures/claude-2.1.302-empty.ansi` and `-typed.ansi`): the input box is the body between the
screen's last two horizontal rules, one line `❯`, a no-break space, then the text. Empty is
`❯ ESC[0mESC[2mTry "fix lint errors"ESC[0m`: the placeholder is drawn faint (SGR 2). Typed is
`❯ hello owner draft` in the default colour.

`Empty` only when all of these hold; anything else is `Text` (the non-faint characters) or `Unsure` (why):

1. The pane is not scrolled back.
2. No marker of a claude.toml blocked or transcript-viewer rule is on the screen (`esc to cancel`, `enter to
   select`, `do you want to proceed?`, `showing detailed transcript`, and the rest of `NOT_THE_INPUT`), nor vim
   mode's `-- NORMAL --` or `-- INSERT --`.
3. The screen has at least two horizontal rules; the last two are the box, with at most 12 non-empty lines under
   it, and exactly one line between them. No `❯` or `>` line elsewhere is ever read.
4. That line starts `❯` at its first column, then a space or a no-break space.
5. Every character after the mark that is not white space is faint (SGR 2 on, until 22 or 0). A colour, grey or
   not, does not make text a placeholder; an extended colour's arguments (`38;5;n`, `48;2;r;g;b`) are skipped, so
   their `2` is not read as faint.
6. No `[` is on the line, faint or not (a pasted-text or image chip).
7. No cell after the line's first is drawn inverse (a cursor Claude draws itself).
8. The terminal's cursor is read, and, when shown, sits on that line at the column after the mark.

The fixtures for the review round were built by hand from the recorded empty screen, each changing one thing
(`src/nirvana_idle_compact/fixtures/`): `pasted-chip.ansi` and `image-chip.ansi` (a faint chip on the line),
`grey-typed.ansi` (the owner's text in the grey `38;2;153;153;153` the screen draws Claude's own hints in),
`multiline-last-empty.ansi` and `multiline-first-empty.ansi` (two lines in the box), `menu.ansi` (a permission
question in place of the box), `no-box.ansi` (the `❯` placeholder line with the two rules taken out),
`scrolled.ansi` (fifteen lines of output under the box), `vim-insert.ansi` (`-- INSERT --` in the footer) and
`dialog-marker.ansi` (`Enter to confirm · Esc to cancel` above an empty-looking box). Each reads as not empty.

Not measured: where Claude Code leaves the terminal's cursor on an empty line. The recordings are screen text and
carry no cursor. The tests place it at the line's start (`ESC[9;3H`); played as recorded, the cursor sits after the
last line and the line reads `Unsure`. If a live Claude leaves the terminal's cursor shown anywhere else, idle
compact never sends; that is the fail-safe direction, and the live check (plan §5) shows which.

This was not re-measured against a live Claude: the work order forbids running `claude`. The recorded screens are
five days old and from 2.1.302.

## The transcript a pane's compact reads (review S3)

`choose_transcript` returns the pane's own transcript or why there is none:

- The pane's foreground job must hold Claude; a shell after the owner quit gives none.
- The id is Claude's own `sessions/<pid>.json` when that file was written at or after the process started (a record
  left by an earlier process with a reused pid is older); else the hook's id, when its transcript was written at or
  after the process started. The record comes first because the hook's id can be stale after `/clear`.
- No id gives none. The folder's newest transcript is never taken here; the agents panel keeps that fallback
  (`nirvana_subagents::resolve_claude_session` is unchanged).
- Another Claude pane in the same folder with the same id, or with none, gives none.
- The process start time comes from `nirvana_subagents::process_creation_secs`, which is known on Windows only and
  `None` elsewhere. **So on any system but Windows, idle compact never sends.**

## The plan was wrong here

1. **"The next deadline is the earliest `idle_since + minutes`"** cannot hold once a pane is checked and left alone:
   that instant is then in the past, and the loop would wake at once, over and over. A checked pane is due again one
   minute later (`RECHECK`), and no check is due at or after the cache's hour (`CACHE_LIFE`). The plan's
   `idle_since: Option<Instant>` became `IdleStretch { since, checked_at, sent, enter_at }` on the terminal.
2. **`is_seat_worker_pane` is empty in the server.** Its set is filled by `read_seat_orders`, which runs in the
   client's subagents poll, a separate process from the headless server. The server still asks it (the plan's rule),
   but in the server the worker test that holds is the argv: a `herdr seat exec` Claude runs `-p`.
3. **"Its transcript resolves to exactly one file"** through `resolve_claude_session` would take the folder's newest
   transcript when no id is known, which can be another conversation's. The review round replaced it for idle
   compact with `choose_transcript`, which takes only an id tied to the process.
4. **"When it sends, the server logs one line naming the pane, the idle minutes and the tokens."** The send is now
   two steps (review S1), so there are two lines: the paste names the pane, the idle minutes and the tokens; the
   Enter names the pane.
