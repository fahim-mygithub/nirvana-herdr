## What was built

1. **§2, the rule** (`src/nirvana_idle_compact.rs`). `decide(&Facts) -> Decision` is the one pure function: it
   returns `Send` or `Skip(reason)`, checking in order rule 1 (a rule exists, so the setting is on and valid), rule 2
   (`Agent::Claude`, not a seat worker pane, the process argv read, no `-p`/`--print`), rule 3 (`AgentState::Idle`,
   idle at least `minutes`), rule 7 (not sent in this stretch), rule 4 (one transcript, last written at least
   `minutes` ago), rule 5 (context at least `min_tokens`) and rule 6 (the input line read and empty). Any `None`
   fact is a skip. Each rule has its own test, built from one sending case with that rule alone broken.
   - `context_tokens` sums `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` and leaves out
     `output_tokens`; `parse_claude_usage` is not used because it adds output.
   - `read_context_tokens` reads the last assistant line from the transcript's tail, widening 64 KB to 8 MB as the
     agents panel does; `file_age` is the transcript's age, `None` when its time is ahead of the clock.
   - `read_outside` reads, in order: the pane shell's foreground job, the Claude process in it and its argv; the
     session id (the hook's, else Claude's own `<config>/sessions/<pid>.json`); the process start time; then
     `resolve_claude_session` with every other Claude pane, so two Claude panes in one folder that nothing tells
     apart resolve to nothing and neither is sent anything.
2. **§2, the idle time and the stretch** (`IdleStretch`, on `TerminalState::idle_stretch`). Set in
   `recompute_effective_state`, the one place every effective state passes: `Idle` starts a stretch at `now` or
   keeps it; any other state clears it, which also clears "sent". A respawned pane's stretch is cleared.
   `next_check_at(minutes)` is `since + minutes`, then a minute after the last check while the pane is left alone,
   and `None` once sent or at the cache's hour.
3. **§2, the server** (`src/app/nirvana_idle_compact.rs`). `idle_compact_deadline` is the earliest due check of the
   idle Claude panes, and is one of the deadlines in `next_headless_loop_deadline_with_git_refresh`, so the server
   sleeps until then. `handle_scheduled_tasks_headless` calls `nirvana_idle_compact(now)`, which returns at once
   unless a check is due. For each due pane it marks the check, reads the screen (`visible_ansi`), takes the outside
   facts, builds `Facts` and calls `decide`. On `Send` it marks the stretch sent first, then types `/compact` as
   `herdr agent prompt` types a prompt (`encode_api_submission_parts`, bracketed paste when the pane asks for it,
   Enter 300 ms later through `queue_user_input_submission`), and logs one line: `nirvana: idle Claude sent
   /compact` with `pane`, `idle_minutes` and `tokens`. A skip logs its reason at debug.
4. **§3, the setting** (`src/config/idle_compact.rs`). `[ui.idle_compact]` with `enabled = true`, `minutes = 50`,
   `min_tokens = 50000`. `minutes` outside 1..=59 or a negative `min_tokens` is a config diagnostic, at startup and
   on reload, and the rule is then `None`: a config in doubt sends nothing. The numbers are signed so a negative
   one reaches that message instead of failing the whole config's parse. `ConfigEdit::IdleCompact(bool)` writes
   `[ui.idle_compact] enabled`. The server keeps `App::idle_compact` and replaces it in `apply_live_config`, so a
   changed setting applies without a restart.
5. **§3, the settings section**. `ClientSettingsSection::IdleCompact` ("idle compact"), between Toasts and
   Integrations, with On and Off, opening on the current value and saved through `ConfigEdit` like the other
   sections.
6. **§4.** 68 controls in `nirvana/controls.d/idle_compact.py`. Tests use temporary folders, a thread-local seat
   worker stand-in, and `crate::nirvana::with_test_home` for the server tests; none reads a real transcript, a real
   pane, `~/.claude`, or calls herdr.

## How the input line is decided empty

`src/detect/manifests/claude.toml` reads Claude Code's prompt box as the body between the screen's last two
horizontal rules (`prompt_box_body`), its line starting `❯`; that is how the `live_prompt_box` rule calls a pane
`idle`. The manifest only asks "is there a prompt box"; it does not say whether the line holds text, so it cannot
decide rule 6.

The text on the line comes from `nirvana_run::prompt_line_text`, which `herdr run wake` uses, built from screens
recorded in a herdr pane from Claude Code 2.1.302 on 2026-10-18 (`src/nirvana_run/fixtures/claude-2.1.302-empty.ansi`
and `-typed.ansi`). An empty line is `❯`, a no-break space, then a placeholder drawn faint:
`❯\u00a0ESC[0mESC[2mTry "fix lint errors"ESC[0m`. A typed line is `❯\u00a0hello owner draft` in the default colour.
So the screen is read with its colours (`TerminalRuntime::visible_ansi`), text drawn faint, bright black or in a
grey is the placeholder, and anything else after the mark is the owner's. `Some("")` is empty; text is a skip; no
prompt line found (`None`, for example a scrolled or covered screen) is a skip. The test
`idle_compact_reads_the_recorded_claude_input_line` plays both recorded screens into a pane runtime and reads them
back the way the server does.

This was not re-measured against a live Claude: the work order forbids running `claude`. The recorded screens are
five days old and from 2.1.302.

## The plan was wrong here

1. **"The next deadline is the earliest `idle_since + minutes`"** cannot hold once a pane is checked and left alone:
   that instant is then in the past, and the loop would wake at once, over and over. The nearest thing that keeps
   the ledger: a checked pane is due again one minute later (`RECHECK`), and no check is due at or after the cache's
   hour (`CACHE_LIFE`), when a compact would no longer read from cache (L1, L3). The plan's
   `idle_since: Option<Instant>` became `IdleStretch { since, checked_at, sent }` on the terminal.
2. **`is_seat_worker_pane` is empty in the server.** Its set is filled by `read_seat_orders`, which runs in the
   client's subagents poll (`client/mod.rs` `take_changed`), a separate process from the headless server. The server
   still asks it (the plan's rule), but in the server the worker test that holds is the argv: a `herdr seat exec`
   Claude runs `-p`.
3. **`resolve_claude_session` without a start time** takes the newest transcript in the folder of any age, which
   could be an older conversation's. The server passes the Claude process's start time
   (`process_creation_secs`, Windows only; `None` elsewhere) and Claude's own session id from
   `<config>/sessions/<pid>.json` when the hook reported none.
