## The §3 probe

`probe.py` in this folder, run 2026-10-23 with Claude Code 2.1.310 from Python with a list argv, in
`<scratchpad>/p25-probe/run1/`, with a copy of this worktree's `nirvana/claude` as the Nirvana home (so no hook wrote
into the installed home), `BROWSER` set to `C:\Windows\System32\where.exe`, every `CLAUDE*`, `HERDR_*` and
`NIRVANA_*` variable of the calling session left out, and `NIRVANA_HERDR_HOME` at the probe's home. One run per
variant, 11 runs in all (the first pass's parser expected one JSON object and Claude Code printed the list of
messages; the script then read that run's saved output again instead of running it twice). The argv is
`nirvana_launch::nirvana_claude_args` with `--model haiku` and without `--rc`, which would register the run with the
owner's remote-control session and adds no context:

```text
claude -p ok --output-format json --plugin-dir <probe>\home\nirvana\claude --agent nirvana --model haiku
       --effort medium --append-system-prompt-file <probe>\home\nirvana\claude\ROLE.md --name Nirvana
       --settings <probe>\home\nirvana\claude\settings.json --chrome [variant]
```

Every run was one turn (`num_turns` 1) on `claude-haiku-5-5`. The reading is the turn's `input_tokens +
cache_creation_input_tokens + cache_read_input_tokens`. The tool list varied by two MCP tools between runs (236 to
238: `claude.ai Uber Eats` connected in some runs and failed in others), so readings within about 130 of today are
noise.

## What was built

1. **§2, the trigger** (`src/nirvana_fresh.rs`, the Stop hook's half). `herdr nirvana stop` calls `stop_hook`, which
   reads the pane from `HERDR_PANE_ID` and the transcript from the hook's JSON, and calls `on_stop_in`:
   - `last_end_of`: the ended runs whose `opened.orchestrator_pane` is this pane (`herdr seat run` records the
     orchestrator's `HERDR_PANE_ID` there), the latest end;

     last clear; a `--resume` keeps the file and its start;
   - the context: `nirvana_idle_compact::read_context_tokens`, the last assistant turn's input + cache read + cache
     write;
   - `trigger` (pure): the end at or after the session's start, and the context above `fresh_above`
     (`seats.toml` `[constants] fresh_above = 120000`; a table without the line reads 120k).
   When it holds, `<home>/nirvana/fresh/<pane>.json` gets the record (run, end, context, transcript, project, its
   second, `by = "stop"`); a record this hook wrote for the same run keeps its second. When it does not hold, a record
   the hook wrote is taken back; the owner's own stays.
2. **§2, the clear** (`src/app/nirvana_fresh.rs`, the server's half). `fresh_deadline` is one of the server loop's

   `<pane>.sent` names the record's second.

## The plan was wrong here

1. **"herdr types `/clear` into Nirvana Claude's pane, then the handoff note as the next prompt."** The work order
   requires idle compact's rule, Enter only after a read shows exactly the typed text. A note of up to 8,000
   characters over several lines is shown by Claude Code as a `[Pasted text …]` chip, which `read_input_line` reads
   as `Unsure` by design (plan 27 review B1), so a typed note could never be confirmed and would always be erased.
   Built instead: the note reaches the fresh session through the plugin's SessionStart hook (`herdr nirvana digest`,
   source `clear`), whose output Claude Code adds to the session's context. It is built from files, kept to its
   budget, and journaled as the plan says; what differs is that no prompt is typed, so the fresh session does not take
   a turn until the owner types. Not measured live: that Claude Code runs the plugin's SessionStart hook with source
   `clear` after a `/clear` typed by herdr (its hooks page says SessionStart's matchers include `clear`).
2. **"It uses the wake's own rules (`wake_decision`)."** Replaced, per the work order, by idle compact's stricter
   reads (`read_input_line`, `owner_key`, `after_paste`); `wake_decision`'s looser `prompt_line_text` is not used.
   The wake's rules themselves are kept: only Nirvana Claude, only idle, owner quiet `OWNER_QUIET_S`, empty line.
3. **"The Stop hook ... records a pending fresh start for the pane"** cannot by itself reach the typing: the hook
   is a separate process and the server has no channel from it. The record is a file per pane, which the server looks
   for on its own schedule (2 s, 10 s, 30 s into each idle stretch, then once a minute), the same cross-process shape
   as the owner's key file.
4. **§3.1's probe cannot measure `Artifact`, `SendFeedback` or `ReadNotifications`.** A `-p` session does not list
   them (the `init` message's tools, every run), so their readings are noise (125 to 131), and the 500-token rule
   leaves them uncut. §1's estimate for `Artifact` alone was about 9.4k in the interactive session. An interactive
   measurement (`/context` in a live Nirvana Claude) would be needed, which the work order does not allow here.
5. **§1's "`superpowers` is enabled twice, and its 'using-superpowers' hook text is about 1.1k"** did not hold for the
   first turn: with the second plugin off the reading fell by 136. Claude Code lists each `superpowers:` skill once
   across the two plugins.
6. **"The probe also checks that one turn can still run `herdr seat pick --help`."** Not run: the work order's prompt
   is `ok` only. What was checked is that every needed tool is in each run's tool list.
