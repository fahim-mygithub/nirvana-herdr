## The §3 probe

`probe.py` in this folder, run 2026-10-23 with Claude Code 2.1.310 from Python with a list argv, in
`<scratchpad>/p25-probe/run1/`, with a copy of this worktree's `nirvana/claude` as the Nirvana home (so no hook wrote
into the installed home), `BROWSER` set to `C:\Windows\System32\where.exe`, every `CLAUDE*`, `HERDR_*` and
`NIRVANA_*` variable of the calling session left out, and `NIRVANA_HERDR_HOME` at the probe's home. One run per
variant, 11 runs in all (the first pass's parser expected one JSON object and Claude Code printed the list of
messages; the script then read that run's saved output again instead of running it twice). The argv is
`nirvana_launch::nirvana_claude_args` with `--model haiku` and without `--rc`, which would register the run with the
owner's remote-control session and adds no context:

```text
claude -p ok --output-format json --plugin-dir <probe>\home\nirvana\claude --agent nirvana --model haiku
       --effort medium --append-system-prompt-file <probe>\home\nirvana\claude\ROLE.md --name Nirvana
       --settings <probe>\home\nirvana\claude\settings.json --chrome [variant]
```

Every run was one turn (`num_turns` 1) on `claude-haiku-5-5`. The reading is the turn's `input_tokens +
cache_creation_input_tokens + cache_read_input_tokens`. The tool list varied by two MCP tools between runs (236 to
238: `claude.ai Uber Eats` connected in some runs and failed in others), so readings within about 130 of today are
noise.

## What was built

1. **§2, the trigger** (`src/nirvana_fresh.rs`, the Stop hook's half). `herdr nirvana stop` calls `stop_hook`, which
   reads the pane from `HERDR_PANE_ID` and the transcript from the hook's JSON, and calls `on_stop_in`:
   - `last_end_of`: the ended runs whose `opened.orchestrator_pane` is this pane (`herdr seat run` records the
     orchestrator's `HERDR_PANE_ID` there), the latest end;
   - `session_began`: the transcript's creation time. A `/clear` starts a new transcript, so this is the session's
     last clear; a `--resume` keeps the file and its start;
   - the context: `nirvana_idle_compact::read_context_tokens`, the last assistant turn's input + cache read + cache
     write;
   - `trigger` (pure): the end at or after the session's start, and the context above `fresh_above`
     (`seats.toml` `[constants] fresh_above = 120000`; a table without the line reads 120k).
   - (review B1) also: no open run of this pane (`open_of`); the end at most `FRESH_WITHIN` (10 minutes, a
     hypothesis) old; and no owner prompt at or after the end (`owner_prompt_since` over the transcript's last 8 MiB,
     `owner_prompts`' own filter; a line that does not parse, an owner prompt with no readable time, or a tail with no
     line timed before the end is a doubt). The transcript is read last, only when every other rule holds.
   When it holds, `<home>/nirvana/fresh/<pane>.json` gets the record (run, end, context, transcript, project, its
   second, `by = "stop"`); a record this hook wrote for the same run keeps its second. When it does not hold, a record
   the hook wrote is taken back; the owner's own stays, and is never overwritten (review nit).
2. **§2, the clear** (`src/app/nirvana_fresh.rs`, the server's half). `fresh_deadline` is one of the server loop's
   deadlines, over the Claude terminals herdr started as Nirvana Claude (agent name `nirvana` or `nirvana-<n>`). Each
   idle stretch looks for the pane's record at 2 s, 10 s and 30 s after it began (the Stop hook may still be running
   when herdr reads the pane idle), then once a minute; a record left for now is tried again after `OWNER_QUIET_S`.
   `decide` (pure) types only when: no idle compact paste is in flight on the pane, a readable record waits that the
   server has not cleared for (`<pane>.sent`), the pane's Claude process has Nirvana Claude's argv
   (`nirvana_run::is_nirvana_claude_argv`), the pane is `Idle`, the owner's last key is at least `OWNER_QUIET_S` old
   (idle compact's `owner_quiet_breach`), and idle compact's strict `read_input_line` reads `Empty`. Then `/clear` is
   pasted, and the reads after it are idle compact's own (`after_paste`, through `after_clear_paste`, which shows it
   a line of exactly `/clear` as its command and a line of `/compact` as a doubt): Enter at the first try of 300 ms,
   1 s, 2 s that reads exactly `/clear` with the owner quiet, the paste erased with 6 Backspaces at 3 s if it echoed
   later, a read at 4 s; the owner's key or any other line ends it with nothing erased. Once Enter went, the mark
   `<pane>.sent` names the record's second (written with `write_atomic`, review nit).
   Review S1 and S3: `decide` also skips a stretch whose idle compact already went (`IdleStretch::sent`); forgets a
   Stop's record older than `FRESH_WITHIN`, with its mark, before the mark is read; and for a Stop's record sends only
   while the pane's transcript, read as idle compact reads it (`read_outside_and_transcript`, `choose_transcript`),
   is the record's (`same_transcript`: separators, a `\\?\` prefix and case aside). Any doubt skips.
3. **§2, the note** (the SessionStart hook's half). `herdr nirvana digest` calls `session_start_hook`; on source
   `clear` with a record for the pane, `on_session_start_in` builds the note from files (`note_input`, then the pure
   `note`), appends `Kind::Fresh { pane, by, context, note_tokens }` to the ended run's journal, removes the record
   and the mark, and the digest prints the note after itself, which Claude Code adds to the fresh session's context.
   On source `startup` a record is removed (the session is fresh already). The note: the ended run's line (its end,
   its orders and phases, its receipt's path), every open run with its orders and phases (five named), the board's
   sections with their first lines (eight named), the owner's last three prompts verbatim (each cut at 1,500
   characters), the project's lessons index line, and the closing sentence. It is cut to 8,000 characters
   (2,000 tokens as characters / 4) before the closing line, which is always whole.
   Review S1 and S2: the note is printed only when the record's project is the hook's own (`same_folder`); a record
   of another project is forgotten and nothing printed. Source `resume` forgets a Stop's record and keeps the
   owner's. A Stop's note quotes the prompts of the record's transcript; the owner's, of the transcript the hook
   reports.
4. **§2, `herdr nirvana fresh [<pane>]`**: a record with `by = "owner"` for the pane (its own `HERDR_PANE_ID` when none
   is named) and the project's last run that pane ended (`owner_record`). Review S2: no transcript and no context (the
   folder's session record names whichever Nirvana pane of the folder wrote last). A named pane is refused, with the
