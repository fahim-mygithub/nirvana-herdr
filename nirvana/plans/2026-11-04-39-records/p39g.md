# P39g: the message box grows with its text

## The owner, 2026-11-09
"when I type in the chat box then leave the screen then try to retype the textbox doesnt grow with the text size and
it onlt shows the beginning part of the text so I can continue typing where I left off."

## Cause
The box was `<input type="text">` (chat.js), a single line 44 px tall. It can never grow, and when it loses focus
WebKit scrolls it back to the start, so a long draft showed only its first words.

## Change
- chat.js: the box is a `<textarea rows="1">`. `fitDraft()` sets its height to its text, up to six 22 px lines plus
  padding (`DRAFT_MOST`), then it scrolls inside (`.full`). It runs on typing, after a send, on the first draw, and on
  `visibilitychange`, `pageshow` and `resize`, since a box laid out while hidden measures 0. On focus the caret goes
  to the end unless the owner tapped somewhere in the text, and the end is scrolled into view. Enter still sends;
  the IME rule stays. The window listeners are removed with the screen.
- app.css: `.draft` keeps the 44 px pill for one line, with `line-height: 22px`, `resize: none`. The composer row
  aligns to the bottom, so attach and send stay beside the last line.

## Measured
Headless Chromium and WebKit on Windows, 440 x 956, on p39o's stand-in PC (`%TEMP%\p39g\grow_run.py`), not Safari on
an iPhone. Both: empty 44 px; 150 characters 132 px; 750 characters 154 px, scrolling, end in view; after a fake
hide and show with the caret at 0, focus put the caret at 750 with the end in view; a send that the PC took emptied
the box back to 44 px; a send the PC did not answer kept the text. No page errors.
