## The routes

All of them run after `Site::route`'s checks (the Tailscale service's connection, exactly one owner login, another
device's address, this PC's Host, and `same_site`): the dispatch block sits right after the refusal `return` (H5).

| Route | Answer |
|---|---|
| `GET /api/folders` | `{"root": "Desktop\\Pojects", "folders": [{"name", "open", "space", "agent"}]}` |
| `POST /api/folders/open` `{"name"}` | `{"space", "existing": true, "agent"}` or `{"space", "existing": false, "preset"}` |
| `GET /api/cards/usage` | `{"rows": [{"pool", "label", "provider", "fill", "windows" or "word" or "memory"}]}` |
| `GET /api/cards/servers` | `{"remote": {"name", "port"}, "up", "servers": [{"space", "port"}]}` |
| `GET /api/cards/running` | `{"working", "needs", "agents": [{"id", "name", "space", "status", "words"}]}` |
| `GET /newspace.js`, `/cards.js` | the two scripts (served from `pick.rs`, so `routes::ASSETS` is untouched) |

The open is a POST: `same_site` requires `Sec-Fetch-Site` same-origin or `Origin` this page for it, it must be JSON
(415), it must have a length (411), at most 4 KiB. A GET of it is 405; a POST to a card is 405.

## New space (§2.5)

**The same path as "Open Nirvana here".** Explorer's verb runs `herdr nirvana open <folder>` (`nirvana_launch::open`,
`src/nirvana_launch.rs:734`). Its live-window route, `:753-757`: `fresh = !is_server_listening()`, then
`nirvana_preset::at_open(&folder)`, then `invoke_open(&folder, fresh, true)`, then the window's flash and toast.
`invoke_open` (`:939-959`) sends `command.invoke` with `open_command_id(folder, fresh, new_space)`, which is
`nirvana.open:[new:][fresh:]<folder>` (`:460-467`). `nirvana window` does the same at `:858-860`. herdr's app takes it in
`handle_command_invoke` (`src/app/custom_commands.rs:121-127`) and opens it in `nirvana_open_folder`
(`src/app/nirvana_new.rs:70-101`): a new space on the folder, Nirvana Claude started in its root pane by
`nirvana_start_agent` (`:144-206`, resuming the folder's last session by `nirvana_resume`, `:209-214`).

Nirvana Remote runs inside that server, so `fresh` is false, and it sends the same call over the in-process channel
(`herdr::App::call`): `at_open(folder)`, then `command.invoke` with `open_command_id(folder, false, true)`. So the space
gets the folder's preset and the resume exactly as a PC open does. Not sent: the window's flash and toast, which are
for someone at the PC. herdr's answer (`AgentStarted {agent, argv}`) gives the new space's id; the argv stays on the PC.

**The folder the page names.** The page sends `{"name"}`, the name exactly as `GET /api/folders` listed it; the server
never takes a path. `resolve`:
1. `name_ok`: not empty, at most 255 bytes, no control character, no `\ / : * ? " < > |` (so no `..\x`, no `\\?\`,
   no UNC, no drive, no ADS stream), no trailing dot or space (Windows drops them, so `groove-coach.` would open
   `groove-coach`; `.` and `..` end in a dot), not a device name (`CON`, `PRN`, `AUX`, `NUL`, `CONIN$`, `CONOUT$`,
   `COM0-9`, `LPT0-9`, and the superscript `¹²³` forms, with or without an extension).
2. The root is listed again and the name must be one of its entries (`list`): plain folders only, a name starting
   with `.` left out (`.nirvana`).
3. `plain_dir`: the entry itself is read (`symlink_metadata`), and a reparse point or a link is refused.
4. `inside`: root and folder canonicalised, and the folder's parent must be the root.

The path opened is `root.join(name)`, the form Explorer hands the verb (`C:\Users\<user>\Desktop\Pojects\<name>`), so
`folder_key` compares it with an existing space's folder the same way.

**A folder already open.** Before anything is started, `pane.list` is read and any pane whose `cwd` has the folder's
`folder_key` (case and separators ignored, as `nirvana_launch::folder_key` does) names its space: the answer is
`{"space", "existing": true}`, no preset is applied and nothing is invoked. The page then scrolls to that space and
plays the new-row motion. herdr's own `nirvana_space_on` (`nirvana_new.rs:217-239`) would focus a space only when
Nirvana Claude runs there; on a folder with only a shell open it would open a second space, which this check stops.
The listing marks such folders "open". Opens are one at a time (`Local::opening`), so two taps cannot both find the
folder closed.

## The cards (§2.6), and why each field may leave the PC

**Usage.** The sidebar foot draws `nirvana_usage::rows()` (`src/client/shell/sidebar.rs:558`): `foot_rows` over each
reader's last `Source` (`src/nirvana_usage.rs:1320`), less `FOOT_HIDDEN` (`:1308-1315`, Argon and Google's Claude
pool). The window's readers write each `Source` into the shared cache `<Nirvana home>/nirvana/usage.json`
(`start_worker`, `:1286-1293`; `write_source`, `:1044`; `cache_path`, `:1030`), and every window loads it at start
(`:1257-1270`). The card reads that file and runs the same `foot_rows` and filter. It starts no reader: a reader runs
`claude` and `agy`, which the herdr server must not start for a phone. Sent per row: the pool, its label, the
reader's key, the bar's fill, and per window its name, share used, seconds to reset, `stale` and `ahead` (the foot's
age and pace marks), or the foot's word, or the local engine's MiB. Left on the PC: each reading's `source` (the
command that read it) and `resets_text` (Claude's reset as printed, with the owner's time zone). The cache holds no
account, login or e-mail at all (`Reading`, `:169-187`). The page shows one figure per pool, the tightest window, as
the foot's bar does; both windows did not fit the 164 px card (measured below).

**Servers.** The foot's servers block is `server_rows` (`src/client/shell/nirvana_footer.rs:76-93`): each space's
`nirvana_servers` token in the spaces' order. The server sets the token from `nirvana_servers::cached_ports`
(`src/server/client_shell.rs:42-64`, `:113-120`), a cache in this same herdr server process. The card reads that cache
through a new read-only `nirvana_servers::last_ports` (H8), which does not record shells as `cached_ports` does. The
block leads with Nirvana Remote's own row (`nirvana_footer::REMOTE`); a phone that reads the card reached it, so it
is `remote :8443`. Sent: space names (already in `/api/spaces`) and port numbers. No process, command or URL.

**Running.** The tab strip's Running square says, for its agent, "waits on you" (blocked), "working · <tool>" while a
tool call is open in its transcript, else "working" (`running_value`, `src/client/shell/nirvana_mods.rs:119-130`),
the tool from `nirvana_running::cached` over the agent's `nirvana_transcript` token (`:79-83`,
`src/client/shell/composition.rs:244-247`). The square is one agent; the card counts every agent at work (working or
blocked, as the PC list's line counts, `herdr::summary`) and gives each the square's words (`running_words`). The
token is read only when it is a transcript under Claude Code's folder (`chat::is_transcript`, as `/api/chat`). Sent:
pane id, name, space and state (all in `/api/spaces` already), and the words, whose tool part is the tool's name
only ("Bash"); its `detail` (the command, path or query) is not sent.

**How the cards stay current.** `spaces.js` calls `cards.refresh()` on each `spaces` event (one read per 0.8 s
burst), and `cards.js` reads again every 30 s while the page is shown, for usage and servers, which change without a
herdr event. Each read is three GETs: a file read, one `workspace.list`, and `workspace.list` plus `agent.list`, all
in process. This is a timer on herdr's list calls, unlike P39b's spaces view; the PC's own foot reads usage at the
readers' pace (2-4 min) and ports every 3 s, so 30 s adds nothing the PC is not already doing.

## Where the order or the plan was wrong or open

1. **"starts the space through the same path as Open Nirvana here" cannot be fully the same.** The verb also flashes
   the PC's window and shows a toast (`:756-757`); both are for someone at the PC and are left out. The verb's
   `fresh` is false here by construction. herdr's `nirvana_open_folder` switches the PC's window to the new space
   (`switch_workspace`), as the verb does; an open from the phone therefore moves the PC's view.
2. **"A folder already open as a space opens that space instead of a second one."** herdr's path alone does not do
   this: `nirvana_space_on` only knows spaces where Nirvana Claude runs, so a shell space on the folder would get a
   second space beside it. The check is here, on `pane.list`'s `cwd`. "Opens that space" is read as on the phone:
   the PC's window is not switched to it (the verb would focus a Nirvana Claude space; the phone leaves the PC
   alone). If the owner wants the PC to follow, it is one `command.invoke` more in that branch.
3. **The cards come from the same data, not the same process for usage.** The usage square is drawn in the window
   process from its own readers; the server cannot call it. The card reads the file those readers write, which is
   what every window loads at start. A reading the window took in the last moment before its write is the only
   difference.
4. **The servers cache had no read-only accessor.** `cached_ports` records the caller's shells; calling it from the
   card would have overwritten the snapshot's. H8 adds `last_ports` to `src/nirvana_servers.rs`, a file the order
   did not list (neither mine nor P39c's), so it is a hunk like the others.
5. **"Read-only. No credential ..."**: met; nothing in the cards' sources is a credential or an account. The one
   near-personal field, Claude's printed reset with a time zone, is left out.
6. **A 30 s card timer on herdr's list calls.** P39b's rule was no timer polling of herdr for the spaces view; the
   cards' usage and ports change without a herdr event, so they need a timer. Recorded above, not a departure from a
   ledger row.
7. **The plan's §3 row says P39d "may build beside P39c, disjoint files"**: not fully disjoint; five of P39c's files
   need lines (H1-H7). Each hunk is appended after an anchor line and adds no line P39c would also change, except
   that H6 and H7 append after the last line of `index.html`'s scripts and of `app.css`, where P39c may also append.

## Not done, or unsure

- No live run: herdr, Tailscale and the preset are fakes. The real `command.invoke` over the in-process channel has
  no test; herdr's own tests cover `nirvana_open_folder`. Whether `command.invoke` answers inside `App::call`'s 3 s
  (workspace, pane, the agent typed in) is not measured; on a timeout the phone says it failed while the space may
  still open (step 9).
- The real `nirvana_preset::at_open` runs in the herdr server process here, not in a window's process as for the
  verb. It is the same function; its background reading and catalog threads then run in the server. Not measured;
  the PC verb pays the same cost.
- `Local::opening` (one open at a time) has no test.
- The page's tap on a folder, the sheet closing and the scroll to the space ran in no browser: the headless run had
  no POST route. The Rust side of each is tested.
- `last_ports` returns the last read only while some window keeps the server's snapshot asking `cached_ports` (that
  call records which shells to read); with no window attached the ports are the last a window saw. The foot has the
  same data, so the card agrees with it, but a phone with no PC window open may see stale ports.
- Reparse points other than links (a OneDrive placeholder folder) are refused by the attribute check; no test makes
  one.
- `name_ok` refuses `COM¹²³`/`LPT¹²³` but not other Unicode digits; Windows reserves only those three.
