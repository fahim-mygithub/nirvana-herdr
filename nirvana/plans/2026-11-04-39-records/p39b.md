## What was built

- `src/nirvana_remote/http.rs`: a request body, read only when a route asks for it (`Conn::read_body`), after every
  check has passed on the head. `Content-Length` or `Transfer-Encoding: chunked`, nothing else; both at once, two
  lengths or a length that is not plain digits is refused (`framing`). A `Content-Length` over the route's limit is
  refused before a byte is read; a chunked body is counted as it streams and refused the moment it passes the limit.
  A live view writes its head without a length (`encode_stream_head`, which is `encode` less its length line, so the
  safety headers stay in one place). The route now runs on the blocking pool with the socket as a plain
  `std::net::TcpStream`; it comes back to tokio for the answer and P39a's drain.
- `src/nirvana_remote/herdr.rs`: `subscribe` (`events.subscribe`) and `call_socket` (`agent.wait`) over this server's
  own API socket, because the socket server answers those two itself, not the app (`src/api/server.rs:428`,
  `:472`, `stream_subscriptions` at `:811`). `agent.prompt` gets 15 s instead of 3 s.
- `src/nirvana_remote/spaces.rs`: the list (`build`) and the one shared `events.subscribe` (`Feed`).
- `src/nirvana_remote/stream.rs`: the live views (SSE), capped, ended with Nirvana Remote.
- `src/nirvana_remote/chat.rs`: which transcript, bubbles, the live screen.
- `src/nirvana_remote/send.rs`: the send rule, upload names, the uploads folder, the write.
- `src/nirvana_remote/live.rs`: the routes `GET /api/spaces`, `/api/events`, `/api/chat?agent=`,
  `/api/chat/events?agent=`, `POST /api/send`, `/api/upload?agent=`.
- `src/nirvana_remote/routes.rs`: the routes wired after the existing checks; `Site` gains `feed`, `streams`,
  `claude_dir` and `nirvana_home`. `src/nirvana_remote.rs`: the modules, `start` sets the two folders,
  `Serving::end` ends every live view before the listener closes.
- `src/nirvana_running.rs`: `tool_detail` is `pub(crate)`, reused for a tool's folded line.
- The page: `spaces.js` (screen 2), `chat.js` (screens 3 and 5), `app.js` (`postJson`, `upload`, `stream`, `sheet`,
  a screen's cleanup on leave, the icons), `app.css` (the screens, the prototype's sheet, new-row and dots motion),

- Tests in `src/nirvana_remote/tests_live.rs` (32) and one in `tests.rs`; controls in `nirvana/controls.d/p39b.py`

## How the page stays live: Server-Sent Events

The spaces screen opens `GET /api/events`, the chat screen `GET /api/chat/events?agent=<id>`. Each is a plain GET
with a streamed answer: `text/event-stream`, no length, `retry: 2000`, then the whole state as the first event and
each change after it.

- **Through `tailscale serve`.** tailscaled's proxy is Go's `httputil.ReverseProxy` (record p39a read
  `ipn/ipnlocal/serve.go` at v1.102.2). Its `flushInterval` returns -1, flush every write, for a `text/event-stream`
  answer. A WebSocket would need the upgrade carried through and a frame codec here. *Not measured on the tailnet:
  live-check step 3.*
- **iPhone Safari in the background.** Safari drops the connection while the page is hidden. `EventSource`
  reconnects by itself after a drop; the page also opens it again at once on `visibilitychange` and `pageshow`.
  Every stream starts with the whole state, so nothing is lost while it was away. `EventSource` is in Safari since 5;
  nothing else here is newer than `:where()` (Safari 14).
- **herdr restarts on the PC.** The proxy answers 502 until Nirvana Remote is back, and a non-200 closes an
  `EventSource` for good, so `app.js` opens it again after 1 s, doubling to 15 s.
- **No timer on herdr.** One `events.subscribe` per Nirvana Remote, shared by every view (`Feed`): `workspace.created`,
  `.closed`, `.renamed`, `.reordered`, `pane.created`, `.closed`, `.exited`, `.agent_detected`, and
  `pane.agent_status_changed` for each agent's pane. That last one takes one `pane_id`
  (`src/api/schema/events.rs:76`, no all-panes form), so when the agents change the feed subscribes again with the
  new panes. Events 150 ms apart are one change (at most 1 s), then `workspace.list` and `agent.list` rebuild the
  list, and a list that differs is sent. When the stream ends the feed subscribes again (0.5 s, doubling to 10 s).
  The chat view reads its transcript's length and time once a second: a file on the PC, not herdr.
- **Slots.** A view holds one of P39a's 32 connections, so at most 6 are open; a 7th ends the oldest (a phone back
  from the background opens a new one before the old is found dead). A comment every 20 s finds a reader that went
  away; a view ends after 15 min and the page reconnects. `Serving::end` ends them all: without it, a herdr server's
  shutdown would wait on each view's blocking thread (`stopping_nirvana_remote_ends_the_pages_live_views`).

What the feed leaves behind: nothing, since the review round. An old stream's reader is told to stop and ends within
25 ms (see "Review round", S3).

## Which transcript (§2.2)

The page names an agent by its herdr pane id only; the server looks it up in `agent.list` and requires its space in
`workspace.list` (`Site::found`), and every path comes from herdr's answer for it.

1. The agent's `nirvana_transcript` token. The herdr server sets it for each Claude from the Claude process's own
   session file and folder (`src/nirvana_spaces.rs:503-515`, `read_claude_session(&config, pid)` at `:505`:
   `<claude config>/projects/<slug(cwd)>/<session_id>.jsonl`); the Running square reads the same token
   (`src/client/shell/nirvana_mods.rs:82`). It is the live conversation, the file "Open Nirvana here" resumes once
   that Claude has stopped.
2. With no token: the folder's session record, which is what "Open Nirvana here" resumes from
   (`src/app/nirvana_new.rs:213` calls `resume_session`, which is `resume_session_at` at
   `src/nirvana_launch.rs:331`, reading `session_record_path` at `:304`). Reused as is, with no age limit, so its
   checks hold: a plain session id, the file's stem that id, its folder Claude Code's own name for the agent's
   folder, and the file there.

Either way the file must be `<plain id>.jsonl` directly in a folder of `<claude config>/projects/`, compared
canonically (`chat::is_transcript`). A token that fails is refused, and does not fall through to the record.

## Send (§2.3, §2's failure paragraph)

`POST /api/send` `{"agent", "text", "files", "mode"}`, JSON only (415 otherwise), 64 KiB at most. The message goes
through `agent.prompt` over the in-process channel (the headless server routes it to the app's deferred handler,
`src/server/headless.rs:3044`), the same call as `herdr agent prompt`: herdr pastes the text into the pane, bracketed
when the pane asked for it, then Enter, through the pane's own input queue (`submit_agent_prompt`,
`src/app/api/agents.rs:209`, `queue_user_input_submission` at `:261`). To the agent it is typing on the PC.

- **queue**: `agent.prompt` as is. Claude Code takes a message entered during its turn without stopping it, holding
  it until it next can.
- **send now**: `agent.send_keys ["esc"]` (Claude Code's interrupt; `esc` is a key name at
  `src/config/keybinds.rs:1315`), then `agent.wait` until idle, done or blocked, at most 8 s, then `agent.prompt`.
  If it has not stopped by then, the message still goes, and so waits in Claude's queue; the answer says
  `"stopped": false` and the page says so.
- While the agent works and no mode was given, the answer is 409 `{"choose": true}`; nothing is typed until the
  owner picks.
- A blocked agent (a question or a permission on its screen) is not typed into: 409, before anything is sent. herdr
  refuses it too (`agent_blocked`, `agents.rs:171`).
- **No lock.** PC and phone both write into the pane's one input queue, each in the order it reached herdr; two
  sends at once are two `agent.prompt`s (`two_sends_at_once_both_land`). Not prevented: text the owner typed on the
  PC and has not sent sits in Claude Code's box, and the phone's message is pasted after it and sent with it.

## Paste and upload

`POST /api/upload?agent=<id>`: the body is the file, its `Content-Type` names the extension. It goes to
`<agent's folder>/.nirvana/uploads/` (herdr's `cwd` for the agent, else `foreground_cwd`).

- **Names are the server's**: `phone-<yyyymmdd>-<hhmmss>-<8 hex>.<ext>` with the extension from a fixed list of types,
  else `.bin`. Nothing the client sends (query, `X-File-Name`, `Content-Disposition`, its file name) is used, so no
  traversal, no reserved Windows name, no `:` stream, and `create_new` never overwrites. Written as
  `<name>.partial`, renamed when whole; nothing is left on a failure. A send turns only these names, present in that
  folder, into paths (`is_upload_name`), each after a space, quoted when it has one (review round, S2).
- **Out of git: a `.gitignore` holding `*` inside `uploads/`.** Not `.git/info/exclude`: that is per repository, so in
  a linked worktree (whose `.git` is a file) it is shared by every worktree of it, it does nothing in a folder that is
  not a repository, and it is a write under `.git/`. The `.gitignore` works in any folder, touches no tracked file,
  and `*` matches itself, so `git status` stays clean. `.nirvana` or `uploads` that is a link or a junction
  (`FILE_ATTRIBUTE_REPARSE_POINT`) is refused.
- **50 MiB** (50 × 1024 × 1024 bytes): over it by `Content-Length` is a 413 on the head, before the agent is looked
  up; chunked over it is a 413 the moment it passes. The page refuses over 50 MB before sending.
- **P39a's limits with a 50 MB body.** The body must not go 10 s without a byte, and must average 64 KiB/s after its
  first 10 s (a 50 MiB upload gets 810 s): `a_slow_upload_gets_408_and_leaves_no_file`. An upload holds one slot; the
  33rd connection still waits (`the_33rd_connection_waits_while_a_50_mb_upload_holds_a_slot`).
- **On the phone**: the attach sheet's "Paste screenshot" uses `navigator.clipboard.read()` where Safari allows it
  (it shows its own Paste button), else asks for a long-press Paste into the box, which arrives as a file on the
  `paste` event; "Photo library" is `<input type="file" accept="image/*">`; "File" any type.

## Trust

Every new route runs after P39a's checks in `Site::route`: the Tailscale service's connection, exactly one owner
login, another device's address, this PC's Host, and for a POST `Sec-Fetch-Site`/`Origin` from this page. Only then is
herdr asked or a body read. `a_refused_caller_gets_nothing_from_the_new_routes`: another user, no user, the owner's
login from this PC's own address, a cross-site POST and a POST with neither header all get 403 and the refusal text;
herdr is asked nothing (the fake's call log is empty) and no folder is made. Controls `p39b_send_after_checks` and
`p39b_chat_after_checks` put a route before the checks and the test goes red. The CSP is unchanged: no
`unsafe-inline`, so no inline script or style; the page sets no `style` attribute and parses no markup.

## Where the order or the plan was wrong or open

1. **"Live from herdr's events.subscribe ... no timer polling of herdr" holds for this server, not inside herdr.**
   herdr's own `events.subscribe` reads its event hub every 100 ms (`CONNECTION_POLL_INTERVAL`,
   `src/api/server.rs:30`), and its per-pane status subscription takes a `pane.get` snapshot through the app when its
   history has nothing (`subscriptions.rs` `poll_batch`). Nirvana Remote asks herdr nothing on a timer; herdr's API
   does, as it does for `herdr` on the command line.
2. **`events.subscribe` and `agent.wait` are not on the in-process channel.** P39a's `herdr.rs` assumed every method
   was; those two need the socket, so Nirvana Remote dials its own server's pipe for them.
3. **"Every space with its sparkle mark"**: the sidebar sparkles a space while anything in it works
   (`SPARKLE_FRAMES`); otherwise the page shows a still mark coloured by the space's state. The prototype's per-space
   glyphs and branch names (`master`, `main`) are not in herdr's lists; left out.
4. **Screen 5's Esc button** is P39c's (plan §2.4), so it is not drawn; "send now" uses Esc inside the send.
5. **The order's "50 MB"** is read as 50 MiB.
6. **P39a's CSS reset `.nv button` outweighed every single-class button rule** (0,1,1 against 0,1,0), so screen 1's
   `.pc` rows had no padding and kept their height only from `min-height`. It is `:where(.nv) button` now, which gives
   screen 1 the prototype's 16 px row padding. Read from the cascade rules; the headless run measured only the page
   after the change (rows 73 px high, 16 px inside the card), and the owner has not seen it.

### What changed

- **S1, whose transcript** (`chat.rs`, `live.rs`). The folder's session record is taken only for a Claude
  (`chat::is_claude`: the `nirvana_kind` token, else herdr's agent label through `Kind::from_agent_label`, as
  `nirvana_spaces` reads a row with no kind token yet) that is the only Claude of this herdr in that folder
  (`Found::others` carries herdr's other agents). A Codex or Antigravity agent gets no transcript: the chat shows the
  note "No transcript for this agent: the PC's screen is below." and the live screen from `agent.read`. **A second
  Claude in a folder with no token yet** gets no record either, since the record could be the other's; it shows the
  same note and screen until its own token comes, never another agent's conversation. Beyond the review: the chat
  view re-read the transcript on a state change only while it had none, so a Claude shown the folder's record would
  never move to its own token. It now resolves the transcript again on each change of the agent's row and, when the
  file differs, sends the whole chat from the new file.
- **S2, phone text** (`send.rs`). Every C0 control but `\n` and `\t` is dropped before `agent.prompt` (so `ESC`, and
  with it any sequence such as `ESC[201~`, and `\r`), and DEL, and the C1 controls U+0080-U+009F (U+009B is a
  one-character CSI to a terminal that reads C1; the review did not name C1). A file's path follows the text after a
  space, not a newline, quoted when it holds a space (a space's folder may: `3D-Printer Flow`). A `\n` the owner typed
  inside the text stays: in a pane with bracketed paste (Claude Code asks for it) it is text; in one without, it is an
  Enter, as with `herdr agent prompt`.
- **S3, the feed** (`spaces.rs`, `herdr.rs`). (a) A second snapshot right after `events.subscribe` answers, sent when
  it differs, and a new subscription at once if the agents moved in between. (b) A wait before every subscription
  after the first, 0.5 s doubling to 10 s, put back to 0.5 s only when a stream carries an event: a herdr that acks and
  closes is asked three times in 3.2 s, not in a loop. (c) Old reader threads end: each subscription has a `stop` flag
  set when the feed leaves it (`Stop`'s drop), and the socket is read by peeking (`herdr::Polled`, the pattern of
  `api::client`'s status probe), so a quiet stream's reader sees the flag within 25 ms. No thread or pipe outlives its
  subscription.
- **S4, a socket that never answers** (`herdr.rs`). `call_socket` waits `timeout_ms + 2 s` (`socket_wait`, `MARGIN`),
  else 3 s, and then answers an error; `events.subscribe` waits 3 s for its ack. **The review's fix would not have
  worked on the owner's PC**: `set_recv_timeout` on a Windows named pipe is `Unsupported`, which
  `set_timeout_best_effort` swallows (`src/api/client.rs:133-148`; the status probe's comment at `:209` says the same).
  The deadline is in `Polled` instead, which does not need a timeout from the pipe.
- **S5, a closed agent** (`app.js`, `chat.js`). A stream's handlers get the view's `close` as a second argument; `gone`
  calls it and writes "This agent has closed on the PC.", and an `onerror` after `close` changes nothing, so the note
  stays and nothing reconnects.
- **S6, a stream re-checks its caller** (`stream.rs`, `live.rs`). I re-check, not shorten the lifetime: `stream::run`
  takes `still`, asked each `WAKE` (1 s), and a view ends when the owner's login or this PC (`Site::caller`, the
  `owner` and `me` the supervisor writes) differs from what it was when the view opened. It holds because every
  refusal those two drive is a value the supervisor changes in place: another login after a sign-in to another
  account, both `None` when Tailscale cannot say who the owner is. What it cannot see: a device dropped from the
  tailnet while the owner is the same. This server has no per-device list (the identity header is the user's); that
  view ends when tailscaled's connection to it fails (a write fails within `WRITE_TIMEOUT` of the next event or
  `BEAT`), or at `LIFETIME`.
- **S7, cross-site reads** (`routes.rs` `same_site`). A GET or HEAD of `/api/` is refused when it sends a
  `Sec-Fetch-Site` that is not `same-origin` or `none`, or an `Origin` that is not this page. A read with neither is
  let in, and the doc comment argues it: a same-origin GET carries no `Origin`, so Safari before 16.4 sends nothing on
  the page's own reads, and another PC's probe of `/api/hello` (`pcs::Https`) sends neither; a browser that sends
  neither cannot mark a request cross-site, so the check has nothing to read. The page's own files are not held to it
  (a link from another site opens `/`). Why the page still passes on iPhone Safari: its `fetch` and `EventSource` are
  same-origin, and WebKit sends `Sec-Fetch-Site` since Safari 16.4; *that version is the order's and my reading, not
  measured on the owner's phone (live-check step 4).*
- **N2**: a view opened in the last second is not opened again. Beyond the review: `pageshow` also fires on the first
  load, so every first load opened two views back to back, not only a Safari wake. **N3**: no send on the Enter that
  confirms an IME candidate (`isComposing`, or `keyCode` 229). **N5**: a chunk size is `1*HEXDIG` with whitespace
  allowed only before an extension; `+1` and ` 1` are 400. **N4**: a 413 or 400 answered on the head of a large
  upload reached a client that wrote before it read as a reset: the drain after an answer read 64 KiB, then closed with
  the rest unread. It now reads up to 8 MiB (still within `DRAIN_TIME`, 1 s). Measured with the control in place: the
  client's read failed `ConnectionAborted` (os error 10053) with no answer; with the fix it reads the 413.
