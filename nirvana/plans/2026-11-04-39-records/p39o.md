# P39o build record: an error page when the phone cannot reach the PC

Branch `p39-offline`, from 88be52d6 (master, alpha 0.58.2). Built 2026-11-09 by "Opus high - Nirvana Remote offline
page". No version bump, no CHANGELOG: the merge does those.

The owner, 2026-11-08: "Can you also add a tailsscale check to the UI when it fails to connect. Like a error page."

## The departure from P39e, and why it is safe

P39e's worker cached nothing and had no fetch handler (record p39e, "Service worker"): a cached page would hide a new
version, and "with the PC out of reach a cache helps nothing". The second half is what the owner's ask overturns:
with Tailscale off on the phone, the PC asleep, or Nirvana closed, no byte comes from the PC, so an error page has to
come from the phone. The first half still holds, and is kept by the design below: while the PC answers, the page is
always the running build's.

## What was built

- `src/nirvana_remote/shell.rs` (new). The shell is `files()`: `routes::ASSETS` (the page, its css and screen
  scripts), `pick.rs`'s two scripts, and `alerts::FILES` without `/sw.js` (the alerts script, the manifest, the
  icons). Nothing under `/api/`. The **build tag** is `<VERSION>-<FNV-1a 64 of every shell file's path and bytes and
  the worker template>`, e.g. `0.58.2-` and 16 hex digits. `worker()` serves `sw.js` with `'NIRVANA_BUILD'` and
  `['NIRVANA_SHELL']` replaced by the tag and the JSON list of paths (one source of truth: the server's own
  tables); `index()` writes the tag into `<meta name="nirvana-build">`. `/api/hello` answers with the header
  `Nirvana-Build: <tag>`.
- `page/sw.js`. Kept as it was: the push and notificationclick handlers, and P39e's `install` (skipWaiting) and
  `activate` (claim) lines. Added:
  - **Cache name** `nirvana-shell-<tag>` (`CACHE = PREFIX + BUILD`). A second `install` listener fetches each shell
    path once (`cache: 'no-store'`) and keeps only `ok` answers; a failed file is skipped, never fatal, because a
    failed install would leave the phone with no worker and so no alerts. A second `activate` listener deletes every
    `nirvana-shell-*` cache that is not this build's.
  - **One fetch handler.** It returns without answering (the browser goes to the network as with no worker) for
    anything not a `GET`, another origin (the Google fonts), any path under `/api/` (every live view and call), and
    any path not in `SHELL`. For a shell file it is **the PC first**: the fetch goes to the PC; an `ok` answer is
    returned and copied into the cache. The cached copy is returned only when the PC gives no answer (a network
    error, or none in `WAIT_MS` = 4 s), or answers 403/421 (the login checks) or 502/503/504 (tailscaled with
    Nirvana gone): the shell then explains it better than a bare text page. After a failure, the next shell files
    go straight to the cache for `DOWN_MS` = 15 s, so a page load waits once, not once per script. A late answer
    still refreshes the cache.
  - **How a stale shell cannot outlive a release:** (1) while the PC answers within 4 s, the network copy is what
    the page gets; (2) every merge bumps the version (CLAUDE.md rule 16) and any changed shell byte changes the tag,
    so `sw.js`'s bytes change, the browser installs the new worker at the next visit (the worker script is served
    `no-store`), and its activate deletes the older cache; (3) a page that did come from an older cache (the PC was
    slow, then answered) compares its meta tag with `/api/hello`'s `Nirvana-Build` and reloads, at most once a
    minute (`sessionStorage`; if storage throws it does not reload, so it cannot loop).
  - The CSP is unchanged: the worker fetches only its own origin (`connect-src 'self'`), and a cached answer keeps
    the headers it was stored with, the CSP included.
- `page/app.js`. The reach check and the error screen, in the shell, so it serves every screen:
  - Every `getJson`/`postJson` goes through `reached()`, the upload's XHR reports `error` and its status, and every
    live view reports `open` (`answered`) and `error` (`lost`).
  - **Cases** (`verdict`, `unreachable`): no answer and `navigator.onLine === false` is **offline**; no answer
    otherwise is **unreachable** ("Can't reach your PC"); a 502/503/504 that is not JSON is **nirvana** (tailscaled
    answered, Nirvana did not: our own 502 from `/api/pcs` is JSON and does not count); 403/421 is **refused**: "The
    PC refused this phone. This phone's Tailscale account is not the PC's." The page never claims the VPN state; the
    first check says "This page cannot see the VPN; only you can."
  - **Checklist**, most likely first, each with how to check it: Tailscale is on on this phone (the VPN switch in
    the Tailscale app); the PC is on and awake; Nirvana is open on the PC (the sidebar's bottom row `● remote
    :8443`, dot green); this phone is online (`navigator.onLine`, read live). The offline case puts the last first;
    the nirvana case puts Nirvana first; the refused case has its own three (the account, the PC's name, Nirvana just
    started).
  - **Timing.** A live view that drops shows "Reconnecting to the PC…" at once, as before; if nothing has answered
    after `LOST_MS` = **10 s**, `/api/hello` is asked (at most `PROBE_MS` = 6 s), and if it does not answer the
    error screen shows. So the screen comes 10 to 16 s after the PC drops (measured 10.2-10.3 s in Chromium, where
    the stand-in refused at once). A request with no answer waits the same 10 s (a Wi-Fi to mobile handover loses a
    request or two and should not flash the screen); a refusal or gateway answer shows the screen at once. The page
    also asks once as it opens, which is what shows the screen at once on a page served from the cache.
  - **Try again** asks now; the automatic tries come 2, 4, 8, 15 and then every 30 s, with a countdown; the
    `online` event and the page coming back to the foreground ask at once.
  - **Back where the owner was.** The error screen lies over the open screen (`.reach`, z-index 30, re-appended if
    a screen changes under it). When the PC answers: the screen goes, every live view opens again at once (not at
    the end of its back-off), and a screen whose data load (a GET) failed while down is drawn again with its own
    params. A failed send or upload does not redraw, so the chat keeps the typed text.
- `page/index.html`: the meta line. `page/app.css`: the error screen, in screen 1's layout and Nirvana Dark colours
  (brand row, title, a card of numbered checks, Try again in the send button's teal).
- `routes.rs`, `alerts.rs`, `nirvana_remote.rs`: the three serving hooks and the module lines.
- `tests_offline.rs` (new, 4 tests); `tests_alerts.rs`: P39e's "no fetch handler, no Cache Storage" became "one fetch
  handler", so `p39e_sw_no_fetch` (which adds a second) is still red; `tests_live.rs`: P39b's page test matched any
  `addEventListener('visibilitychange'`, which the error screen's own listener also matched (control
  `p39b_page_visibility` went green); it now names the live view's line.

## Safari

- In a Safari tab (not the home-screen app) a service worker still runs on iOS 16.4+ (and earlier), so the cached
  error page works there too once the page has been opened once with the PC reachable.
- **The very first visit while the PC cannot be reached cannot show this page**: nothing is cached yet, so Safari
  shows its own "Safari cannot open the page". The same holds after the owner clears website data, and for the
  home-screen app, which has its own storage separate from Safari's.
- iOS may evict a site's storage after weeks without a visit (WebKit's 7-day rule applies to script-writable storage
  of sites not added to the home screen); the home-screen app is exempt. Not measured here.
- Not run on Safari or an iPhone. The browser runs below are Chromium and Playwright's WebKit on Windows.

## The owner's live check, in order

1. On the PC, Nirvana open at this build. On the iPhone, open Nirvana from the home screen once while everything is
   up (this fills the cache; the alerts row and spaces show as before).
2. Turn Tailscale off on the phone (the Tailscale app's VPN switch). Close Nirvana from the app switcher and open it
   from the home screen: "Can't reach your PC" with the four checks and "Trying again in 2 s".
3. Turn Tailscale on. Within the countdown (or tap Try again) the PC list comes back.
4. Open a space, then turn Tailscale off again: "Reconnecting to the PC…", then after about 10-16 s the error screen.
   Turn it on: the same space comes back, live.
5. Optional: Airplane mode shows "This phone is offline". Signed in to Tailscale with another account: "The PC
   refused this phone".
6. Optional: after the next merge, the first open shows the new version line (the new worker installs; the old cache
   is deleted).
