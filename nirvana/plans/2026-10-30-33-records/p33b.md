## How the review is queued, and why

The brief asked for "the nearest way that exists". Two exist: `request_review` (books a seat and returns a
`herdr seat run ...` line for Nirvana Claude to type) and `send_back` (picks, books, writes the order, journals
`seated` and starts it with `nirvana_worker::launch_worker`). The review follows `send_back`: it needs no Opus turn
to start a Flash review after every gated order, which is what L3 bought, and it is the launcher every send-back
child already uses. Nirvana Claude gates the review when it delivers, as every delivery (ROLE.md step 5). A merge
queued at `herdr run end` lands in a run that has ended, which wakes nobody; `settle`, run at the next `run end` of
the project, gates any pending review that has delivered. No second launcher; no digest line is needed.

## Where the plan was wrong, or could not be built as written

1. **`lesson_reviews_per_day` in `[constants]`.** `Constants` is `deny_unknown_fields` in `nirvana_seat.rs` (P33a's),
   so the line would refuse the whole table. Built: the value is read as plain TOML (`nirvana_review::per_day`),
   default 20, and the seats.toml comment says where it goes; hunk H4 adds the field.
2. **One new class breaks a test in P33a's file**: the default-table test lists the 19 classes exactly (hunk H3).
3. **`lesson_ops` cannot reach a Work Report** until the worker's `REPORT_SCHEMA`, `REPORT_KEYS` and
   `check_report` know it (hunk H2): the schema is `additionalProperties: false`. The gate here checks the report
   with `lesson_ops` set aside, so it works before and after H2.
4. **`review_skipped` as a journal event** would be a new `Kind` in `nirvana_run.rs`. Built as an axis named
   `review_skipped` in the subject's `gated` event, which is journaled.
5. **"Nothing to keep is ... the default"** departs from Hermes ("'Nothing to save.' ... should NOT be the default");
   the plan's rule is kept and the comment on `RULES` says so.
6. **The cap counts merges too**: a merge is a `lesson-review` order. A hypothesis, said here.
7. **Rollback** restores a part's counters as they were at the merge; what the umbrella earned after goes with it.

### What the containment does and does not hold (B3)

- **Claude reviewer.** `--disallowedTools` with `DENIED`, by the tool names this machine's Claude Code lists. Not
  measured live: no builder may run `claude`. A tool Claude Code adds later that writes is not on the list. The
  list is a deny list because the order asked for one; `--tools Read,Grep,Glob` would be an allow list, if Claude
  Code's print mode takes it, which is unverified here.
- **agy reviewer.** agy has no tool filter and runs with `--dangerously-skip-permissions`, so it can write anywhere
  its user can. What holds it: its cwd is `<run>/reviews/<id>/` (not the project root, where live workers edit), its
  brief says it can only read, and its gate refuses the ops and fails the review when `lessons/` changed in a way
  herdr's writes do not explain. What does not: a write to project source, to `index.json` (counters move with every
  order, so it is not compared), or to the writes log itself, which an agent that knows the format could forge. The
  check catches a reviewer that writes a lesson file directly; it does not stop a hostile one.
- **The writes log** grows by one line per herdr write in `lessons/` and is never trimmed. A hypothesis that this
  stays small: one or two lines per kept lesson.

### Where the order could not be built as written

1. **"Review and merge evidence is at least 20 characters."** A merge op carries no evidence (§3.4's op is
   `merge {slugs, name, steps}`), so the rule binds review ops only.
2. **"Only text the worker's stream holds and herdr did not write counts."** Built as the three exclusions the order
   names (order copy, brief, lesson bodies). `stream_strings` still counts the worker's own assistant text, as
   before; restricting it to tool results would change the worker-lesson rule of O5 too.
3. **"Compare file shas" between queue and gate.** A plain compare fails every review gated after another order kept
   a lesson, so herdr logs each of its own writes and the compare forgives a change that a logged write explains.
