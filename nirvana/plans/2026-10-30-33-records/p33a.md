# P33a build record: agent profiles per project

Built on `p33a-profiles` from 191ecb2e, by "Opus high - P33a profiles build", 2026-10-30. Plan:
`nirvana/plans/2026-10-30-33-profiles-and-learning.md` §2.

## What was built

- `src/nirvana_profiles.rs` (new): the parser for `<project>/.nirvana/profiles/<name>.md`, the run copy, the order
  copy's lines, the narrowing, the claude flags, the digest lines, the template and `herdr profile
  list|show|new|check`. Tests in `src/nirvana_profiles/tests.rs`.
- `src/nirvana_seat.rs`: `Request.profile` (a `Narrow`: name, model, family, effort). A seat the profile refuses is
  skipped as `SkipKind::Profile`, after the family filter and before the floors, so floors, reserves and modes still
  act. The profile's effort replaces the class's (and a class seat's own effort); the SOTA lift, the step down and the
  cap at high still apply, and Balanced's climb steps down from the profile's effort. A no-seat reason starts
  `with profile <name>: `. The pick carries `profile`, so a `--book` lease remembers it. `seat pick --profile <name>`
  takes the profile's class when `--class` is not given and joins its needs before plan 29's routing.
- `src/nirvana_worker.rs`: `seat run --profile <name>` (`seat_order_with`). The file is read once; its bytes are
  parsed, hashed and copied to `<run>/profiles/<name>-<sha16>.md`. The class comes from the profile when the order
  names none, its needs are joined before plan 29's routing, the `--send-ok` check and plan 31's warning, and the
  pick is narrowed. The order copy starts with `Profile: <name>` and `Profile sha256: <hex>`. The `seated` event's
  reason ends `; profile <name> sha256 <hex>`. `seat exec` reads the run copy, checks its sha before every start
  and gives the worker the profile. Claude gets `--append-system-prompt-file <run>/profiles/<name>-<sha16>.body.md`
  and `--disallowedTools` when the list is not empty. agy gets the body quoted at the top of its order copy. The
  reseat narrows the child's pick from the run copy. A booking made with one profile refuses a `seat run` with
  another or with none. An order whose text already says `Profile:` is refused unless it is seated with that
  profile.
- `src/nirvana_claude.rs`: the SessionStart digest prints the profile lines after the digest.
- `src/client/shell/nirvana_profiles.rs` (new) and `src/client/shell/nirvana_mods.rs`: a Profiles group at the end of
  the Preload panel. `e` opens a profile's file through Preload's `command.invoke` edit path. `n` asks for a name of
  `[a-z0-9-]`, writes the template and opens it. Space on a profile row says how a profile is used.
- `nirvana/claude/ROLE.md` and `nirvana/claude/skills/seat/SKILL.md`: seat an order that fits a profile with
  `--profile`. The incident is plan 31's audit: 22 of 22 GUI orders were seated with no server.
- `nirvana/controls.d/p33a_profiles.py`: 42 controls.
- `src/main.rs` (`mod` and the `profile` verb) and `src/client/shell.rs` (`mod`): registration only.

## Measured

- Tests: 16 `p33_` tests. In the full nextest run 4398 of 4399 passed. The one failure is
  `windows_plugin_pane_commands_resolve_from_plugin_root_with_cwd_override`, which fails on master too.
- Controls: 42 of 42 `p33a_` controls reddened their test. The 6 older controls whose find text sits in changed lines
  were rerun alone and all 6 passed: `p31_seat_prints_no_prompt`, `p31_seat_no_warning`,
  `p29_seat_pick_drops_claude_only`, `p29_exec_no_servers`, `p29_exec_starts_without` and
  `jevr_advice_always_printed`.

  make. It is live check 1 in plan §6.

## Where the plan was wrong, or silent

1. **"The `seated` event journals the profile name and the sha."** `Seated` is in `src/nirvana_run.rs`, which this
   package does not own. A new field breaks every `Seated { .. }` literal: `nirvana_gate.rs:2179`, the gate tests,
   `nirvana_retro.rs:1017`, the run tests, `nirvana_subagents.rs:2311` and the worker tests. P33b owns two of those
   files. Built instead: the name and the full sha go in the `seated` event's `reason`
   (`...; profile slicer sha256 <64 hex>`), and machines read the two lines of the order copy. A typed field is a
   follow-up for the merge, if wanted.
2. **The example's `class: gui`.** No class `gui` exists in `seats.toml`. `herdr profile check` flags it: "class gui:
   no such class in seats.toml".
3. **The copy's path.** The plan suggests `<run>/profiles/<name>.md`. Two orders in one run can be seated with two
   versions of one profile, so the copy is `<run>/profiles/<name>-<first 16 of the sha>.md`.
4. **The agy body is quoted** (`> ` on each line, between `## Profile: <name>` and `(end of profile <name>)`). Raw
   body lines at line start would be read as gate lines: a body line `owns: x` or `test: y` would change what the
   gate checks. A test proves that a body's `test:` line does not reach `nirvana_gate::spec`.
5. **`disallowed_tools` on agy.** The plan says what Claude gets and does not say what agy gets. Only the claude argv
   can carry `--disallowedTools`, so a profile with a non-empty list takes a claude seat only (plan 29's
   `claude_only`). `seat exec` refuses to start such an order on agy.
6. **The digest's ceiling.** `DIGEST_MAX_CHARS` is 540, and ten descriptions of up to 120 characters do not fit. The
   profile lines print after the digest, outside the ceiling, at most 10 of them plus a count line.
7. **`--override` "keeps its meaning".** I read this as: an override still cannot take a seat that a filter skipped,
   and a profile's refusal is such a filter, like a need.
8. **A profile body is refused when it contains `--send-ok`, plan 31's `SEND_LINE` or herdr's footer mark.** The plan
   names only a key. The footer mark is refused because `write_order` gives no footer to a text that already holds
   it.
