## What was built

1. **Step 1 (§2): The spawn guard**
   - Added pre-tool check on `Agent` tool use in `src/nirvana_claude.rs` to enforce:
     - An `Order:` line is present and names an order with an active, unexpired lease in `leases.json`.
     - The lease is not for an agy CLI seat (which must be started via `herdr seat run`).
     - The spawn's model/seat matches the booked seat, and the spawn's effort does not exceed the booked effort.
   - Distinct, actionable refusal messages guiding the agent on exact commands to invoke.
   - Unit tests covering all refusal scenarios and valid booking matching in `src/nirvana_claude/tests.rs`.

2. **Step 2 (§3.1): The orchestrator's seat**
   - Implemented `orchestrator_seat(&table, &world)` in `src/nirvana_seat.rs`:
     - Efficient: `sonnet medium`
     - Balanced: `opus medium` when max pool climb `t < 0.5`, switching to `sonnet medium` from `0.5`. Falls back to `opus medium` when readings are stale or missing.
     - SOTA: `opus high`
   - Added CLI subcommand `herdr seat orchestrator [--json]` in `src/cli/seat.rs`.
   - Unit tests on fixed worlds across all modes and climb thresholds in `src/nirvana_seat/tests.rs`.

3. **Step 3 (§3.2): The launch**
   - Updated `nirvana_claude_args` and `launch_args` in `src/nirvana_launch.rs` to dynamically query the orchestrator seat rule for the active mode.
   - Falls back gracefully to `claude-opus-5-5 medium` if the table or usage readings fail to load.
   - Routed Restart Claude through `launch_args` via `restart_argv` in `src/app/nirvana_restart.rs` so restarts preserve conversation while picking up current mode seat.
   - Unit tests in `src/nirvana_launch/tests.rs` and `src/app/nirvana_restart/tests.rs`.

4. **Step 4 (§3.3): Mid-session tracking & Seats square**
   - At `SessionStart`, `digest_cli` writes `<home>/nirvana/sessions/<session_id>.json` recording the running seat and effort.
   - `UserPromptSubmit` notice hook (`check_seat_notice` in `src/nirvana_board.rs`) compares running seat with active mode rule, emitting a single notice line on change and persisting notification state.
   - Seats square reads running session and displays orchestrator row as the first row in `src/nirvana_seats_square.rs` and `src/client/shell/nirvana_seats.rs` (`Nirvana Claude · <seat> <effort> · <detail> [· restart to switch]`).
   - Unit tests in `src/nirvana_claude/tests.rs` and client snapshot tests in `src/client/shell/tests/nirvana_seats.rs`.

5. **Step 5 (§2, §3.3): Documentation & Worker Agents**
   - Updated `nirvana/claude/ROLE.md` to stop claiming static Opus 5.5 medium, referencing the session digest and notice instead, and adding directives for subagent bookings and `research.web`.
   - Updated `nirvana/claude/skills/seat/SKILL.md` with booking requirements and `research.web` classification.
   - Updated all five `worker-*` agent descriptions to state that a booking comes first.

## Review fix (orchestrator, 2026-10-20)

- **The notice and the square read the cache only.** The build computed the rule in the `UserPromptSubmit` notice and
  in the Seats square through `live_world`, which re-reads a stale source by running `claude /usage` and
  `agy /usage`: every prompt after five idle minutes would wait on two CLI reads. Under test, with no cache, the
  square ran the real `claude /usage` on the owner's sign-in; the square test's "sonnet medium" came from the
  owner's 71% week. Nextest took 66 s against plan 19's 30 s. Now `nirvana_seat::cached_world` (usage.json and
  leases.json) feeds the launch, the notice and the square; `herdr seat orchestrator` keeps `live_world`, as
  `herdr seat pick` does. The square test writes its own usage.json.
- **No folder record, no running seat.** `running_seat_for` fell back to the newest seat record of any folder,
  which showed another project's seat and read every file of `sessions/`. The fallback is gone; the test gains a
  case for another project's record.
- Controls `p20_square_reads_the_home_cache` and `p20_square_no_other_folder_seat`.
- **The build's live check read the owner's install home:** `herdr seat orchestrator` from a debug build with no
  `NIRVANA_HERDR_HOME` resolves to the installed home. The order forbade it. Its line above is the owner's mode,
  Efficient; the live check after the install replaces it.
