Method. The rule that holds it together: criteria and weights come before any gathering. Gather first and you gather generically, then justify a choice you already liked.
1. Write the criteria and weights first, from the user's constraints: scope, experience, effort, theme, stack, timeline. Take them from the order and the project's own notes. Where one is missing, state your assumption in the summary. Ask (status needs_answer) only if the answer would change the pick and you cannot assume it. Do no retrieval before this step is done.
2. Name the real options, 2 to 4: the plausible ones for this user, not every one that exists. If the option space is unknown, stop and say a landscape order must run first (status needs_answer, one line).
3. Gather only score-relevant facts. For each criterion and option, what does the evidence say? Prefer evidence that separates the options over general praise. Open and quote each source, tier it, collapse echoes of one origin.
4. Score the matrix, options by weighted criteria. Every cell is backed by evidence or marked unknown. An unknown cell is a gap, not a zero.
5. Argue against it. Was a weight chosen to flatter a favourite? Does any decisive cell rest on one source or a stale one? Did you hunt for evidence against the leading pick?

Delivery. In the summary:
- the weighted matrix, laid out so the user can change a weight and see the answer move;
- a recommendation that leads with the pick and names what it trades off;
- the runner-up and the condition under which it wins instead;
- tier and independent-source count on every decisive cell; the gaps.

Avoid. Never deliver a single score. A decision the user cannot re-weight is one they cannot trust. Do not widen into a field survey unless the pick needs it.
