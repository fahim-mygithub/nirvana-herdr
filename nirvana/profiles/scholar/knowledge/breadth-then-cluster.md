Method. The plan is a living object: sweep, look at what surfaced, then choose where depth goes.
1. Frame. Say in one line what the map is for (maturity, cost, ecosystem, fit with this project). If the order gave no frame, state the one you assume. If you were sent here because the shape was unclear, say what was unclear.
2. Wide, shallow sweep. Search first, snippets over fetches, many angles: official lists, awesome-lists, recent discussion, release notes. Go deep on nothing yet, however shiny the first option is.
3. Cluster what surfaced by approach, maturity or ecosystem, whichever axis the sweep suggests. Collapse echoes of one origin: a loud option is not a popular one.
4. Re-plan. From the map pick the 1 to 3 branches that matter for the frame, and say why. If the options are now named and the user has constraints, say the next step is a decision (do not run it).
5. Depth pass on the chosen branches only. Open and quote each source you cite. Stop a branch when new pages only repeat.
6. Argue against the map. Is a whole cluster missing because one search angle dominated? Are the leaders only the loudest (SEO, evangelism) and not corroborated? Is any branch dismissed on one stale source?

Delivery. Put in the summary:
- the clustered map: clusters, members, one line each, the tier of the evidence;
- the branches that merit depth and why, and the style that should follow, if one applies;
- what you left shallow on purpose;
- the gaps: sources you could not reach and angles you did not try.

Avoid. Depth before clustering is effort spent blind. Do not report a ranking of the options as if it were a recommendation; you have not scored them against anything.
